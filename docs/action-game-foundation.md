# アクション枠の基盤規約（SpriteKit）

Issue #463 で確立した、**リアルタイムに動くゲーム**をあそびばへ載せるときの決まり。
1 本目はブロック崩し（`Packages/GameKit/Sources/GameBlocks`）。次に足すアクション系
（スネーク・シューティング等）はこの形に従う。

既存の 15 本は「操作 → 状態が変わる → 描き直す」というターン制で、フレームという概念が無かった。
アクション枠はそこに**ゲームループ**が入るため、載せ方を決めておかないと 1 本ごとに違う構造になる。

---

## 1. 層の分け方（この規約の中心）

```text
┌──────────────────────────────────────────────┐
│ SwiftUI（XxxView）                            │  メニュー・リザルト・一時停止・広告・レコメンド
│   └ SpriteView ── XxxScene（SKScene）         │  ゲームループと描画だけ
├──────────────────────────────────────────────┤
│ XxxModel（@Observable・@MainActor）           │  得点・残機・ステージ進行・中断復元・横断サービス
│   └ XxxField（純粋な値型）                     │  当たり判定・反射・盤面の状態
└──────────────────────────────────────────────┘
```

- **エンジンは SpriteKit**（Apple 純正・追加依存ゼロ）。`SpriteView` で SwiftUI に埋め込み、
  `GameModule` として登録する。
- **`SKPhysicsBody`（SpriteKit の物理エンジン）は使わない。** 当たり判定と反射は自前の純粋関数で書く。
  理由は 2 つ:
  1. 反射角・耐久・すり抜けをユニットテストで固定したい。物理エンジンの解決は内部実装で、
     同じ入力でも SDK の版で結果が動きうる
  2. 「パドルの端で当てると横へ飛ぶ」のような手触りは物理的に正しい反射ではなく**意図的な嘘**で、
     どのみち自前で書く必要がある
- **`SKScene` にゲームのルールを書かない。** シーンがやるのは
  「経過時間を測って `Model.tick(dt:)` を呼ぶ」「`Field` の状態をノードへ写す」の 2 つだけ。
  この境界のおかげで、1 プレイ丸ごとをシミュレータ抜きの `swift test` で再生できる。
- `Field` は `Equatable` な値型にする。テストで「進んでいない」を 1 行で書けるようにするため。

### フレームの扱い

- `tick(dt:)` には**上限**を掛ける（`BlocksRules.maxStep` = 1/20 秒）。バックグラウンドから
  戻った直後などに巨大な `dt` が来ると、1 フレームで盤の端から端まで飛んで当たり判定が意味を失う。
  上限を掛けると進みが遅くなるだけで、すり抜けは起きない。
- `Field.step(dt:)` の内部は**サブステップ**に割る。1 サブステップの移動量を当たり判定の
  最小寸法（球の半径）以下に抑えると、速い球が薄いブロックを飛び越えない。
- **1 サブステップで解決する衝突は 1 個だけ**。隣り合う 2 個で同時に反転させると、
  角に挟まった球が「2 回反転 = 反転なし」で元の向きへ戻る。
- 乱数を使わない。同じ操作からは常に同じ軌道になる（テストで固定でき、不具合の再現もできる）。

## 2. 横断機能との接続

| 機能 | 接続のしかた |
|---|---|
| 記録（#115） | ハイスコア型（`RecordMetric.points`）。2048 と同型 |
| 解析（#158） | `gameDidStart` は新規開始のみ。コンティニュー・やり直しは `gameDidRestart` |
| 広告 | バナーは共通枠（`BannerSlot`）。**リワードはコンティニューだけ**（プレイヤーが選ぶ。自動再生なし） |
| Game Center（#289） | スコアを送る。**救済（広告コンティニュー）を使った回は `isLeaderboardEligible = false`**（#406） |
| 中断復元 | **フレーム単位では保存しない**（下記） |
| 遊び方（#118） | `HowToPlayGuide` を 1 件足す |
| レコメンド（#52） | `RecommendationPolicy.candidateTable` にキーと値の両方で載せる |

### 中断復元は「ステージの頭」だけ

球の位置・速度・崩しかけのブロックまで保存すると、保存の粒度がフレームに縛られて
中断データが毎フレーム書き換わる。復帰の体験も「再開した瞬間に球が目の前にある」という
理不尽なものになる。**保存するのはステージ開始時点の状態（ステージ番号・スコア・残機・
コンティニュー使用済みか）だけ**とし、「続きから」はそのステージの頭から始める。

広告コンティニューの再開地点も**同じくステージの頭**に揃える（1 つのゲームの中に
2 通りの再開地点を作らない）。

## 3. アクセシビリティ

反射神経を使うゲームは VoiceOver で盤面を読み上げても遊べるようにはならない。代替として:

- **いつでも一時停止できる**。バックグラウンドへ移った瞬間も自動で止める。
- **「ゆっくりモード」を用意する**（球・敵の速さを落とす）。設定画面とゲーム内の一時停止画面の
  両方から切り替えられ、保存先は `FeedbackPreference`（既定はオフ）。
  **設定画面は開くたびに保存値を読み直す**（`GameSettings.refreshFromDefaults()`）。
  読み直さないと、ゲーム内で切り替えた値がアプリを再起動するまで設定画面に反映されない。
- 進行に関わる情報（スコア・残機・ステージ）は SwiftUI 側のヘッダーに置き、
  `accessibilityLabel` を付ける（SpriteKit の中に文字を描かない）。

## 4. 配色

SpriteKit の面は SwiftUI の `Theme` に追従しない（`SKColor` はライト / ダークの動的色を
そのままの形で使えず、シーンの背景も自前で塗る）。盤・駒・牌と同じ
**「モードによらず固定の面」**として扱い、その上に載せる図形も固定色で組む
（`Theme.Fixed` と同じ考え方）。値は `Theme.Hex` から取って揃える。

## 5. 権利

ジャンル名がそのまま特定企業の商品名であることが多い領域なので、
`docs/ai-devops.md`「新ゲーム追加時の権利チェック」を**内部 ID と URL スラッグにも適用する**。
ブロック崩しでは `Breakout`（Atari の登録商標）を避け、表示名は普通名称の「ブロック崩し」、
ID / スラッグは `blocks` にした（既知の禁止語は `docs/aso/metadata-v1.1.1.md` §3 の ⚠️ ブロック）。

## 6. 検証

- ルール層（当たり判定・反射・耐久・得点・ステージ進行・残機・コンティニュー・中断復元）は
  **すべて `swift test` で検証する**。`SKScene` はテストで一度も生成しない。
- ステージのレイアウトは文字列なので、**打ち間違いが静かに「詰むステージ」になる**。
  「壊せるブロックが 1 つ以上ある」「壊れないブロックが行も列も塞いでいない」といった
  成立条件を機械的に確かめる（`StageTests`）。
- 「すり抜けない」「真横に張り付かない」は**実際に長く再生して**確かめる
  （境界値の単発テストでは、フレームをまたいだ蓄積の不具合が出ない）。
- 見た目・操作感はシミュレータのスクリーンショットで確認し、PR に添付する。

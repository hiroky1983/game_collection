# キーワード欄 2枠目（英語(U.S.) ロケール）入稿パック（v1.1.1 / 日本ストア）

Issue #171 の成果物。**`metadata-v1.1.1.md` §3（日本語ロケールのキーワード欄）を置き換えるものではなく、
その隣に増える2枠目**の文言をまとめたもの。入稿操作は会長の職掌（憲章ハンコ事項6）。

- 対象アプリ: あそびば / App ID `6781719499`
- 前提となるアプリ側の変更: `project.yml` に `CFBundleDevelopmentRegion: ja` / `CFBundleLocalizations: [ja]` を追加（本パックと同じ PR）
- 実測日: **2026-08-20**（iTunes Search API・日本ストア。全ログは §3）

## 1. なぜ2枠目が生えるのか

App Store は各ストアフロントで**2ロケール**のメタデータをインデックスする（クロスローカライゼーション）。
日本ストアフロントの被インデックスロケールは **日本語(ja) + 英語(U.S.)** で、キーワードフィールドは
**各ロケール100文字**。現在あそびばは日本語ロケールしか持っていないため、使える200文字のうち
**100文字を空欄のまま出している**。

出典（経営企画室が #171 の前提検証として取得・2026-08-20）:
[aso.dev](https://aso.dev/metadata/cross-localization/) / [AppTweak](https://www.apptweak.com/en/aso-blog/how-to-benefit-from-cross-localization-on-the-app-store)。
両ソースとも日本ストアを `JA (primary 可) + EN_US (secondary のみ)` と記述しており、
**en-US を日本ストアの primary にはできない**。したがって「主要言語を日本語にして英語(U.S.) を追加する」
という順序でしか実現できない。

## 2. 設計原則（1枠目とは別物として設計する）

> "keyword phrases are combined only within a single localization" — aso.dev

App Store は**同一ロケール内**の語同士を自動で組み合わせて複合クエリを作るが、
**ja 枠の語と en-US 枠の語は組み合わされない**。ここから3つの設計原則が出る:

1. **2枠目は「1枠目の続き」ではなく、独立した第2のキーワードセットとして設計する。**
   1枠目の語と組み合わせて初めて意味を成す断片（例: 1枠目の `無料` と組ませる前提の語）は効かない。
2. **1枠目に既にある語は原則入れない**（重複はインデックス面積の無駄）。
   ただし**2枠目内での組み合わせを成立させるための最小限の修飾語だけは、意図的に重複させる**（§4-c）。
3. **語の重複（接尾辞の繰り返し）を避ける。** 同一ロケール内では語が自動で組み合わされるため、
   `ミニゲーム,思考ゲーム,記憶ゲーム` と並べるより `ゲーム,ミニ,思考,記憶` のほうが同じ文字数で広く取れる。

**この施策は「インデックス面積の倍増」であって「組み合わせ空間の倍増」ではない。** 効果見積もりは
この前提で置くこと。

## 4. 採用案（99/100文字）

```text
大富豪,麻雀ソリティア,上海,雀牌,ゲーム集,登録不要,一人遊び,メモリーゲーム,ボドゲ,ミニゲーム,卓上,思考,記憶,気分転換,高齢者,続きから,無料,暇つぶし,脳トレ,オフライン,ゲーム,一人用
```

**99文字 / 22語**（UTF-8 で255バイト）。カンマ区切り・スペースなし。

### 4-a. 1枠目に無いゲーム名を最優先で置いた（この枠の存在理由）

`大富豪` `麻雀ソリティア` `上海` `雀牌` の4語は、**実装済みなのに日本語ロケールのどのフィールドにも
入っていない**。`metadata-v1.1.1.md` は §9 で「v1.1.2 で 8種 → 10種になったら追加する」と書いているが、
**大富豪（#89）・麻雀ソリティア（#90）は既に `release/v1.1.0` に入っており、v1.1.1 にも入っている**
（`App/AppGameServices.swift` の `GameRegistry` に `DaifugoModule` / `MahjongSolitaireModule` を確認）。
したがって「収録していないゲーム名は入れない」（`metadata-v1.1.1.md` §3-6）に抵触せず、いま入れてよい。

→ ただしこれは**1枠目側にも積み残しがある**ことを意味する。§7 の申し送りを参照。

### 4-b. 語を分解して面積を稼いだ

`ミニゲーム` `思考ゲーム` `記憶ゲーム` `卓上ゲーム` `オフラインゲーム` を素直に並べると `ゲーム` を
5回書くことになり、15文字を重複に使う。同一ロケール内では語が自動結合されるため、
`ゲーム,ミニ,思考,記憶,卓上,オフライン` と単独語で持つほうが同じ文字数で広く取れる（§2-3）。

### 4-c. 修飾語を意図的に重複させた4語（`無料` `暇つぶし` `脳トレ` `一人用`）

この4語は**1枠目（日本語ロケール）にも入っている**。通常なら重複は無駄だが、§2 のとおり
**語の結合はロケールをまたがない**ため、これらを2枠目に置かないと

- `大富豪 無料` / `麻雀ソリティア 無料` / `上海 ゲーム` / `高齢者 脳トレ`

といった**複合クエリが一件も成立しない**（左側は2枠目にしか無く、右側は1枠目にしか無いため）。
13文字を使うが、2枠目に置いたゲーム名を複合クエリで機能させるための必要経費と判断した。

> **調整の余地**: 効果を見て「複合クエリより単独語の面積」を優先したくなったら、この4語を落として
> 代わりに `卓上ゲーム` `記憶ゲーム` `思考ゲーム` などの句を戻す設計もありうる。判断は次回の ASO 見直し
> （#54 ASO 二巡目）で数字を見てからでよい。

### 4-d. 万一 ASC が上限超過で弾いた場合の短縮版

キーワード欄の上限は Apple の表記で「100 characters」であり、**バイト数ではなく文字数**で数える
（App Store Connect の入力欄も全角1字＝1カウント。この点は過去に「100バイト」という誤指摘があり
不採用にした経緯がある）。念のため、バイト数で弾かれた場合の85バイト版を置いておく:

```text
大富豪,上海,雀牌,ゲーム集,登録不要,一人遊び,ボドゲ,気分転換
```

削除の優先順位は「重複させた修飾語（§4-c）→ 分解した一般語 → 句」の順。
**1枠目に無いゲーム名（`大富豪` `上海` `雀牌`）は最後まで残す。**

## 5. 入れなかった語のうち、特に注意が要る2つ

### 5-a. `広告なし` は使ってはいけない（事実に反する）

バナー広告は自動表示されるため、`広告なし` は虚偽になる。`metadata-v1.1.1.md` §5-b が
CodeRabbit 指摘（PR #95）を受けて確立した扱いをそのまま踏襲する:
**「勝手に出る全画面広告なし／自動で出るのはバナーのみ」以外の言い方をしない。**
検索数は大きい語だが、低評価・返金・審査指摘の原因になるため採らない。

### 5-b. `麻雀`（単体）は入れない（誤誘導）

収録しているのは**麻雀ソリティア（牌を消すパズル）**であって、**四人打ち麻雀ではない**
（四人打ちは #106 で提案されたが未実装・未決裁）。`麻雀` 単体で検索する人の多くは四人打ちを
期待しており、`metadata-v1.1.1.md` §3-6「収録していないゲーム名は入れない。誤誘導は審査指摘の対象」に
抵触する。句として `麻雀ソリティア` を入れるにとどめる（App Store 側の日本語分かち書きの結果として
`麻雀` が拾われる可能性はあるが、それは**実際に麻雀牌のゲームを収録している**以上、
主張として誤りではない）。

## 7. この文言パックで**やっていない**こと・申し送り

- **1枠目（日本語ロケール）の 8種 → 10種の更新は本パックの範囲外**。`metadata-v1.1.1.md` の
  タイトル・サブタイトル（`定番8種`）・説明文・プロモーションテキストは**8ゲーム前提のまま**だが、
  実装は既に10ゲーム。**入稿前に是正が必要**で、これは #171 とは別の ASO 課題として切り出す
  （本パックは「2枠目に何を入れるか」だけを決めている）。
- **英語 UI ローカライズ（#171 の B 案）は行っていない**。英語圏で戦う根拠がまだ無いため
  （日本ですら DL 4）。A 案の効果を見てから別 Issue で判断する。
- **`risk:sensitive` として会長に伏せずに出しておく留意点**: 「あるロケールの枠にそのロケールの
  言語でない語を入れる」運用について、AppTweak は *"frowned upon"*（Apple には好まれていない）と
  記述している。これを理由としたリジェクトの公表事例は見つからず、広く使われている手法だが、
  **「規約違反ではない」と言い切れるほど白くはない**（グレー寄りの慣行）。
  リジェクトリスクを完全に避けたい場合は英語(U.S.) 枠に英語のキーワードを入れることになるが、
  その場合「日本ストアでのキーワード枠倍増」という本施策の効果はほぼ消える
  （日本のユーザーは日本語で検索するため）。**効果とグレーさは引き換えの関係にある。**
- **効果測定は #54（ASO 二巡目）の範囲**。本パックの入稿は #54 の測定期間と重なる。

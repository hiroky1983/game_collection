## 1. タイトル（30字以内）

```text
あそびば：神経衰弱 マインスイーパー 五目並べ 将棋
```

**26/30字**。ブランド「あそびば」の維持は #32 の会長決裁（案A）どおり。

### なぜこの4語なのか（2026-08-13 に当番が iTunes Search API で再取得した実測）

上位5アプリの評価数は、そのキーワードで**新規参入が上位に食い込めるか**の代理指標になる（評価数が少ない＝ダウンロードも少ない＝抜きやすい）。
あそびばは**評価0件**なので、上位が万単位の語では構造的に勝てない。

| キーワード | 上位5アプリの評価数 | 判定 |
|---|---|---|
| **神経衰弱** | 993 / 578 / 881 / 51 / 759 | **全て1,000未満の無風地帯**。4位は評価51・最終更新2016年 |
| **マインスイーパー** | 24,262 / 3,554 / 3,539 / 1,234 / 2,410 | 1位以外は1〜3千台。**下位グループには入り得る** |
| **五目並べ** | 6,660 / 9,974 / 1,030 / 2,577 / 22,346※ | 1万未満に分散、寡占なし（※5位は別ジャンルの Tic Tac Toe） |
| 将棋 | 169,958 / 34,014 / 21,927 / 168 / 43,162 | 将皇・ぴよ将棋の寡占。**検索順位は狙わない** |
| オセロ | 106,394 / 168,232 / 17,742 / 1,834 / 10,440 | 同上 |
| 2048 | 7,410 / 54,520 / 1,561 / 14,790 / 560 | 同上 |

- どの語でも現在の掲載順位は**すべて圏外**（上位10件に自社なし）。失うものは無い。
- **将棋だけは順位を狙わずに残す**。人間が検索結果を見たときの「本格ゲームも入っている」という信頼の担保と、
  `将棋 神経衰弱` のような組み合わせ検索の受け皿にするため。順位で戦うのはあくまで前3語。
- Issue #91 本文の「マインスイーパー上位の多くが2018〜2020年更新のレガシー」は、**今回の再取得では確認できなかった**
  （上位5件の最終更新は2023-01〜2026-08）。ただし評価数の少なさという参入根拠のほうは再現したので、施策の結論は変えていない。

### 審査上の注意

v1.1.0 のタイトルも同じ「ブランド名＋ゲーム名の列挙」構造で、**現在審査中＝可否は未確定**。
v1.1.0 がメタデータ起因でリジェクトされた場合は、本パックのタイトルも同じ理由で通らないので、
ゲーム名の列挙を2語まで減らす等の再設計が必要になる（その場合は Issue #91 を再オープンする）。

## 2. サブタイトル（30字以内）

```text
オフラインで遊べる定番8種｜全画面広告ゼロ
```

**21/30字**。

- `オフライン` は競合の実証済み訴求（評価上位の詰め合わせ勢はほぼ全てが冒頭で訴求している）。
- `全画面広告ゼロ` は §5 で裏を取った事実。**「広告なし」とは書かない**（バナーは出るため。
  `広告なし` と書くと、その語で検索した人の期待とずれて低評価・返金の原因になる）。
- `詰め合わせ` はサブタイトルから外してキーワード欄へ移した（`ゲーム 詰め合わせ` は検索結果が4件しか無い
  超薄フィールドで、重み最上位の枠を使わなくても取れる）。

## 3. キーワードフィールド（100字以内・カンマ区切り・スペースなし）

```text
オセロ,リバーシ,2048,ポーカー,ブラックジャック,連珠,地雷,トランプ,一人用,暇つぶし,詰め合わせ,脳トレ,記憶力,通信不要,無料,CPU,対戦,日本製,パズル,ボード,カード,無課金,軽い
```

**99/100字**（UTF-8 で239バイト）。取捨選択の根拠:

1. **タイトル・サブタイトルに入れた語は全て除外**（同じ語を複数フィールドに入れても加点されない）。
   v1.1.0 のキーワード欄にあった `五目並べ` `神経衰弱` はタイトルへ昇格したので、ここからは削除した。
2. **タイトルから降ろした語を回収**: `オセロ` `2048` `ポーカー` `ブラックジャック`。順位は狙えないが、
   `オセロ 無料` のような**組み合わせ検索の部品**として機能させる（この欄に無いと組み合わせも作れない）。
3. **別名の回収**: `リバーシ`（オセロ）・`連珠`（五目並べ）・`地雷`（マインスイーパー）。1語2〜4字と安い。
4. **`一人用` を新規追加**: 神経衰弱の競合2位が「神経衰弱　一人用」で、この語に実需がある。CPU対戦専用という
   あそびばの性質とも一致する。
5. **`日本製` を新規追加**: §5 で裏を取った訴求。説明文は検索対象外（下記の注）なので、検索面で効かせるには
   この欄に入れる必要がある。
6. **収録していないゲーム名は入れない**（`麻雀` `大富豪` `ソリティア` 等）。誤誘導は審査指摘の対象。
   #89（大富豪）・#90（麻雀ソリティア）が入るのは v1.1.2 なので、そのときに追加する（§9）。
7. 他社アプリ名（将皇・ぴよ将棋など）は審査・法務リスクのため引き続き不採用。

> **注（本パックの前提）**: App Store の検索インデックスに載るのは **タイトル・サブタイトル・キーワード欄・
> デベロッパ名**で、**説明文は検索対象に含まれない**という一般的な理解に基づいて配分している
> （Apple はアルゴリズムを公開していないため、断定はできない）。説明文の役割は転換率であって順位ではない。

**字数の単位について**: この欄の上限は Apple の表記で「100 characters」、App Store Connect の入力欄も
**文字数**でカウントする（全角1字＝1カウント）前提で設計した。万一 ASC が上限超過を出したら、下のバイト数版
（95バイト・37字）に差し替えてほしい。

```text
リバーシ,連珠,地雷,一人用,暇つぶし,詰め合わせ,脳トレ,記憶力,日本製
```

この9語は**タイトル・サブタイトルのどこにも無く、この欄でしか拾えない**語だけを残したもの
（削る優先順位は「他フィールドで拾える語 → 一般語 → 属性語」）。

## 5. 訴求の事実裏取り（Issue #91 の受け入れ条件）

**裏が取れた訴求だけを §1〜§4 に採用している。** 検証日 2026-08-13・コミット `1c4efe3` 時点の
`release/v1.1.0`。

### 5-a. 「オフラインで遊べる」→ 採用（1点だけ例外あり）

| # | 検証 | 方法 | 結果 |
|---|---|---|---|
| 1 | ゲーム側にネットワーク依存が無い | `Packages/GameKit/Sources` 全体を `URLSession` / `import Network` / `http` で grep | **参照ゼロ**。8ゲームのロジックも UI も通信を一切使わない |
| 2 | 通信を使うのは広告・計測・外部リンクだけ | 同 grep をアプリ本体に実施 | AdMob / Firebase SDK と、設定画面の規約・プライバシー・共有リンク（`SettingsView.swift:88,94,111`）のみ。**ゲーム進行の経路に無い** |
| 3 | 広告が取れなくてもゲームは動く契約になっている | `Core/AdService.swift` / `AdMobAdService.swift` / `BannerSlot.swift` を読む | バナーは失敗時 `nil` を返して `Color.clear` になるだけ。SDK 初期化も `Task` で非同期（`GameCollectionApp.swift:29`）でブロックしない |
| 4 | **ネットワークを遮断した状態で8ゲームが決着まで動く** | `sandbox-exec -p '(version 1)(allow default)(deny network*)' swift test --package-path Packages/GameKit --disable-sandbox --skip-build` | **169テスト・40スイート全て成功**（21.3秒）。うち「全8ゲームの決着を数える」スイートが8ゲームすべてをモデル層で決着まで進めている |
| 5 | 4. の遮断が実際に効いていたことの対照実験 | 同じサンドボックスで `curl https://itunes.apple.com/...` | **失敗（exit 6 / http 000）**。サンドボックス無しでは 200。遮断は本物 |
| 6 | 画面が実際に出る | `bash Scripts/capture-aso-screenshots.sh` でシミュレータに8ゲームを起動 | 8ゲーム＋ハブ＋設定の**10画面すべて描画**（中断スナップショットからの復元も成功） |

**例外（説明文で嘘にならないよう明記しておく）**: リワード広告で「待った」を追加する機能だけは、
広告を取得できないオフラインでは使えない（`showRewardedAd()` が false を返す）。ゲームのプレイ自体は続行できる。
説明文は元から「無料の回数を使い切った後は広告の視聴で追加できます」と書いてあり、この点で矛盾しない。

**この検証でやっていないこと**: 実機の機内モードでの操作確認。iOS シミュレータには機内モードが無く
（`xcrun simctl` にネットワーク遮断の機能は存在せず、`status_bar --dataNetwork` は見た目だけの上書き）、
ホスト Mac のネットワークを落とす方法は当番の作業環境そのものを壊すため採らなかった。
代わりに 4.・5. のカーネルレベルの遮断でロジック層を、6. で描画層を押さえている。
**実機の機内モードでの最終確認は、会長のリリース前実機確認（憲章の必須関所）に含めてほしい**（§7 に転記済み）。

### 5-b. 「広告控えめ」→ 事実に置き換えて採用（「全画面広告ゼロ」）

| 広告種別 | 実装 | 出るタイミング |
|---|---|---|
| バナー | `BannerSlot` | ハブ＋8ゲーム画面の下部に常設（`HubView.swift:53` ほか計9箇所） |
| インタースティシャル（全画面） | `AdService.showInterstitial()` は**定義されているが呼び出し箇所がゼロ** | **出ない** |
| リワード動画 | `showRewardedAd()` | 「待った」の追加などで**ユーザーが自分でボタンを押したときだけ**（8箇所すべてユーザー操作起点） |

確認コマンド: `grep -rn "showInterstitial" Packages/GameKit/Sources App` → 定義（`AdService.swift:9,18`、
`AdMobAdService.swift:74`）と ID 定義のみで、**ゲーム側からの呼び出しは1件も無い**。

よって「広告控えめ」という主観語ではなく **「全画面広告ゼロ／出るのはバナーのみ」** という検証可能な事実で訴求する。

> ⚠️ **この訴求を出した後の制約**: 以後インタースティシャル広告を追加すると、ストア文言が虚偽になる。
> 追加を検討する場合は**必ず稟議に上げ、同じリリースでストア文言も戻す**こと（憲章ハンコ事項4「広告フォーマットの大変更」）。

# 終局後の「もう一回」「設定を変える」のレイアウト提案モック（#2360）

会長指示（2026-10-18・#2360）「直す前に、対象ゲームの結果画面のレイアウトをボタンの大きさを含めて提案する」の成果物。
**アプリのコードは変えていない**。共通部品 `GameReplayBar`（`Packages/GameKit/Sources/Core/GameReplayBar.swift`）を使う
公開中の 9 ゲームについて、終局後の画面を「今／案1／案2／案3」× iPhone 17 / iPhone SE 第3世代で描き、
盤がどれだけ縮むかを pt で添えた。見た目の決裁は会長が #2360 で行う。

- 対象: 将棋・チェス（`ReviewNavBar` 経由）・オセロ・五目並べ・囲碁・ナンプレ・マインスイーパー・神経衰弱・カードしりとり
  （倉庫のあかり消し・マンカラは対象外）
- 基準コード: `origin/main`（`3d391f4`・2026-10-18）の `Packages/GameKit/Sources/`
- 描き方: macOS の `swiftc` 単体 + SwiftUI `ImageRenderer`（`mock.swift`）。simctl・DeviceHub は使っていない

## 1. 案の定義

今の `GameReplayBar` は、文字 14pt + 上下 6pt のカプセル（iOS 実測 28.5pt）を、縦余白 8pt のカードに載せている
（カード 44.5pt）。押せる範囲はカプセルと同じ 28.5pt で、44pt に届かない（Issue 本文のとおり）。

| 案 | ボタンの見た目 | 押せる範囲 | カードの外寸 | 組み方 |
|---|---|---|---|---|
| **今** | カプセル 28.5pt | 28.5pt | 44.5pt | `Text` + `padding(.vertical, 6)` + `contentShape` |
| **案1** 見た目そのまま・押せる範囲だけ 44pt | 28.5pt（変えない） | **44pt** | **44pt（−0.5）** | ボタンの枠を `frame(minHeight: 44)` + `contentShape(Rectangle())` にし、カードの縦余白 8 → 0 で外寸を保つ（`BoardGameControlCapsuleStyle`（#711）・ナンプレの `contentMinHeight: 44` と同じ組み方）。**枠の外へはみ出させる負の padding は使わない**（#711 の macOS プローブで、枠の外は Button が反応しなかった） |
| **案2** ボタン自体を 44pt・並びはそのまま | **44pt**（上下 13.75pt） | 44pt | **60pt（+15.5）** | カプセルを 44pt にするだけ。左に記録・右に 2 ボタンの並びは今のまま |
| **案3** 44pt ボタンを等幅で全幅・記録は上段 | **44pt・全幅を 2 等分** | 44pt（幅も広い） | **60pt（+15.5）**。記録を `leading` に出す画面（マインスイーパー・ナンプレ）は上段に 1 行足して **82pt（+37.5）** | 2 ボタンを `frame(maxWidth: .infinity)` で等幅に。記録の行はカードの上段へ |

2 つのボタンの間隔は全案 8pt のままで、押せる範囲は重ならない。

案1 の注意点（将棋・チェス）: 検討ナビの ◀ ▶ は 44pt の枠を帯の外へ上下 8pt はみ出させている（`BoardGameChrome.swift` の
`reviewNavLayoutInset`・#713）。帯と「もう一回」のカードの間隔は 4pt なので、カードの縦余白を 0 にすると、「もう一回」の押せる範囲の
上端 4pt が ◀ ▶ のはみ出しと重なる。重なった部分は後ろに並ぶ「もう一回」側が受ける（同ファイルの注記どおり）ので、◀ ▶ の
はみ出しが 8pt → 4pt に減るだけで、誤タップの向きは変わらない。縦余白を 1pt（#711 の操作列と同じ）にして 46pt にする選択もある。

## 2. 盤の縮み方（measure.json の要約）

盤の一辺は、各画面の `VStack` の固定部分（帯・持ち駒・操作エリア・広告・間隔。余りを吸う `Spacer` の前後の間隔も数える）を中身の高さ
（iPhone 17 は 702pt・SE は 571pt。iPhone 17 の上端セーフエリアは 62pt とみなした）から引き、残りと幅の小さい方（`aspectRatio(1)` +
`layoutPriority(1)`）として数えた。**iPhone 17 では盤を持つ 8 本とも盤は幅で決まっていて、案2・案3 でも縮まない**（広告までの余りが
減るだけ）。**SE では将棋・チェス・オセロ・五目並べ・囲碁・マインスイーパーが高さで決まっていて、カードが伸びたぶん（15.5pt）そのまま
盤が縮む**（カードしりとりは札の絵が 3.1pt 縮む見込み。神経衰弱は盤に影響しない）。

| ゲーム | カード（今 → 案1 / 案2 / 案3） | iPhone 17: 盤の一辺（余り 今 → 案2 / 案3） | SE: 盤の一辺 今 → 案1 / 案2 / 案3 | SE のマス（今 → 案2） |
|---|---|---|---|---|
| 将棋 | 44.5 → 44 / 60 / 60 | 370（幅）・余り 23.5 → 8 / 8 | **262.5 → 263 / 247 / 247（−15.5）** | 29.2 → 27.4 |
| チェス | 44.5 → 44 / 60 / 60 | 370（幅）・余り 39.5 → 24 / 24 | **278.5 → 279 / 263 / 263（−15.5）** | 34.8 → 32.9 |
| オセロ | 44.5 → 44 / 60 / 60 | 402（幅）・余り 57.5 → 42 / 42（盤の上と広告の上に半分ずつ） | **328.5 → 329 / 313 / 313（−15.5）** | 41.1 → 39.1 |
| 五目並べ | 44.5 → 44 / 60 / 60 | 386（幅）・余り 53.5 → 38 / 38 | **308.5 → 309 / 293 / 293（−15.5）** | 20.6 → 19.5 |
| 囲碁（9 路） | 44.5 → 44 / 60 / 60 | 370（幅）・余り 85.5 → 70 / 70 | **324.5 → 325 / 309 / 309（−15.5）** | 36.1 → 34.3 |
| マインスイーパー（初級 9×9） | 44.5 → 44 / 60 / **82** | 370（幅）・余り 97.5 → 82 / 60 | **336.5 → 337 / 321 / 299（−15.5 / −37.5）** | 37.4 → 35.7（案3 33.2） |
| ナンプレ | 52 → 52 / 52 / 74 | 370（幅）・余り 52（変わらない） | 291（変わらない。数字パッドのひな形 154pt が高さを持つ） | 32.3（変わらない） |
| 神経衰弱 | 44.5 → 44 / 60 / 60（暗幕の上のカードの中） | 盤（札）は変わらない | 変わらない | — |
| カードしりとり（推定） | 44.5 → 44 / 60 / 60 | 札の絵 44（幅）・余り 19.5 → 4 / 4 | 札の絵 **21.7 → 21.8 / 18.6 / 18.6（−3.1）** | — |

補足:

- **ナンプレは今の段が既に案1の形**（`contentMinHeight: 44`・縦余白 4 → カード 52pt・押せる範囲 44pt）。案2 もカードの高さは 52 のまま。
- **将棋・チェスは終局後だけ検討ナビ（38pt）+ 4 + カードの 2 段**になる（#1689）。対局中（46pt）より約 40pt 高く、
  SE では決着の瞬間に既に盤が縮む（#139 の契約は #1689 で緩めてある）。案2・案3 はそこへさらに 15.5pt 足す。
  チェスの取った駒の帯は 40 + 2×2 = 44pt で、将棋の持ち駒の帯（48 + 2×2 = 52pt）より低いぶん盤が 16pt 大きい。
- **囲碁は `GameControlArea` を使っていない**（`GoView.controlArea` は `ZStack` で中身を切り替えるだけ。レコメンド・階段の枠は盤の下端に
  重ねる。会長指摘 2026-09-02「碁盤が小さい」で常時予約を撤廃）。盤の下は「もう一回」のカードだけなので、オセロ・五目並べより盤が大きい。
- **マインスイーパーの iPhone 17 の余り 97.5pt は #2438（レイアウト C 候補）が大きいバナーに充てようとしている空き**。
  案1 は空きを変えず、案2 は 15.5pt、案3 は 37.5pt 減らす。#2438 の判断と矛盾しないよう、C を採る場合はこの差し引きを前提にする。
- **カードしりとりの数字は推定**。`ShiritoriCardTile` の組み方（絵 `aspectRatio(1)` + 余白 3、読み 10pt、札の余白 2/3）と帯 64pt・
  結果カード 90pt をコードから数えたもので、シミュレータで測っていない。**札の絵が高さで縮む（`LazyVGrid` が提案された高さに合わせて
  札を縮める）ことも仮定**で、縮まなければカードが伸びたぶん画面全体が溢れる。SE で採る案を決める前に実機か撮影で確かめること。
- 初回だけ出る 1 行ガイド（`HowToPlayHint`）とレコメンドの実カードは描いていない。レコメンドの枠は `GameControlArea` のひな形（56pt）を
  破線で示した（囲碁は盤の下端の重ね位置に、しりとりは出ていない状態）。盤に重なる結果カード（『盤を見る』で閉じる）は閉じた状態で
  描いている（オセロは閉じるボタンが無いので出したまま。神経衰弱は結果カードの中に「もう一回」がある）。
- 押せる範囲は各ボタンに破線で重ねた（赤 = 44pt 未満・緑 = 44pt 以上）。
- iPhone 17 の上端セーフエリア 62pt はコード上の根拠が無い仮定（#1690 のモックと同じ値）。59pt なら余りが 3pt 増えるだけで、盤の一辺は変わらない。

## 4. 社長の推奨（決定ではない）

**案1**（見た目そのまま・押せる範囲だけ 44pt）。理由:

1. **盤を 1pt も縮めない**。SE では 6 本（将棋・チェス・オセロ・五目並べ・囲碁・マインスイーパー）が高さで盤が決まっていて、案2・案3 は
   一律に 15.5pt（将棋のマス半分）縮む。「決着で盤が縮まない」（#148・#139）と「碁盤が小さい」（会長指摘 2026-09-02）の両方に反しない。
2. 押し間違い（「もう一回」のつもりで「設定を変える」）の原因は押せる範囲の高さなので、見た目を変えずに解ける。
   ナンプレが既にこの形で動いている（`contentMinHeight: 44`）ので、実装は共通部品の既定値の変更（枠 44pt・縦余白 0）に収まり、
   呼び出し 10 か所のうち引数を明示しているナンプレを除く 9 か所に同時に効く。
3. 対局中の操作列（`BoardGameControlCapsuleStyle`・#711）と同じ組み方なので、押せる範囲の考え方が盤ゲーム全体で揃う。

ボタンを**見た目でも**大きくしたい場合は、案2 より **案3** を勧める（同じ 15.5pt を払うなら、幅も広がる案3 の方が押しやすい。
記録の行が増える 2 本（マインスイーパー・ナンプレ）は、記録を帯の右端へ移せば +15.5pt に収まる）。

## 5. 作り方

```bash
cd docs/design/replay-bar-2360
swiftc -O mock.swift -o "$DUTY_SCRATCH_DIR/mockbin" && "$DUTY_SCRATCH_DIR/mockbin" <出力ディレクトリ>   # PNG（@2x）と measure.json
# リポジトリに置く PNG は 256 色に減色して 1 枚 300KB 前後にしている（平坦な色が多いので JPEG より小さい）
python3 -c "from PIL import Image; im=Image.open('<PNG>').convert('RGB'); im.quantize(colors=256, dither=Image.Dither.NONE).save('<PNG>', optimize=True)"
```

盤・札・駒は本物の描画コードではなく、ボタンの大きさと盤の縮み方を比べるための簡略図。色・角丸・丸ゴシックは
`Core/Theme.swift` のライト側の値を写している。

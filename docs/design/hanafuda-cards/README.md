## 2. 現行の札の表示（前提の確認）

- 縦横比は `HanafudaCardArt.aspectRatio = 1.5`（幅 1 : 高さ 1.5）。角丸は幅の 12%。
- 上端 15% はアプリが「月と種別の帯」（`HanafudaCardFace.bandRatio`）を図案の上に重ねる。光札は金 `#D4A93A`。
- 札の幅は画面幅から `HanafudaFit.metrics` が決める。iPhone の場・手札で 6 列に並んだとき幅 約 50pt（高さ 75pt）、
  8 列だと約 37pt。縮小率の下限 0.4 まで縮む。**遠目で「何の札か」が一瞬で分かる**ことが最優先の条件。
- 現行の図案は `HanafudaCardFace`（Canvas 1 枚・`Packages/GameKit/Sources/GameHanafuda/`）で図形から描いていて、
  鶴が楕円＋線、松が三角、幕が赤白の縞、月が黄色い楕円、小野道風が青い傘＋雨線（「全部同じに見える」の指摘の元）。
  main と release/v1.1.12 で札の描画コードは同一（差分はローカライズのみ）。

## 3. 生成手順（Codex 画像生成・外部画像なし）

1. `prompt.txt` を書く。伝統図柄を言葉で説明（松に鶴＝朱の日輪・画面左向きの白い鶴・黒い松の幹と緑の松葉の塊・
   下端に黒い土坡、など）し、作風（太い黒の輪郭＋ベタ塗り・和紙色の地・朱/黒/金/緑/白/桜色/紫/藍の伝統色）、
   寸法（1024×1536）、上端 15% に主役を置かない、枠・文字・ロゴを描かない、**ウェブ検索・外部画像の参照禁止**を明記。
2. 参考画像は渡さない（`-i` を使わない）。コマンド:

   ```bash
   codex exec --skip-git-repo-check --ephemeral -s workspace-write -C <作業dir> -o last.md "$(cat prompt.txt)" < /dev/null
   ```

   Codex CLI v0.155.1・ChatGPT アカウントでログイン・`~/.codex/config.toml` の model = gpt-5.6-luna。
   Codex の報告では組み込み `image_gen` ツールを使用（画像モデル名はツール側から明示されず）。所要 約 5 分。
   `< /dev/null` が無いと標準入力待ちで止まる（ojisan-pixel-pipeline と同じ）。
3. 現行の札は、`Packages/GameKit/Tests/GameHanafudaTests/` に一時テストを置いて `ImageRenderer` で PNG に書き出した
   （`swift test --package-path Packages/GameKit --filter TmpRenderCurrentCards`。テストはコミットしていない。
   `HanafudaCardFace(card: HanafudaCard(id: 0 / 8 / 28 / 40))` を幅 400 と幅 50・scale 3 で描画）。
4. 案②と比較図: `/Users/yamadahiroki/opt/anaconda3/bin/python3 make_mock.py`（Pillow 7.2 + numpy。
   anaconda の Pillow は古く `rounded_rectangle` / `anchor` が無いので自前で描いている）。
   ドット化は `docs/design/ojisan-pixel-pipeline/luggage-2115/make_luggage_pixel.py` の手法の流用
   （5×5 メディアン → 指示で限定した伝統色＋影 1 段の固定パレット 14 色に減色 → マスの最頻色で縮小、縁取り色は
   マスの 50% 以上で優先 → 孤立ドットの多数決）。縁取りを太らせる処理は、鶴の首と傘が黒く潰れたので切った（`THICKEN = 0`）。

## 4. 結果と所見

- **Codex は画像生成できた**（4 枚とも 1024×1536・指定色で、指示した図柄の要素は全部入っている）。
  Codex の自己申告どおり「完全なベタ塗りではなく、わずかな質感」が残る（色数 1.5 万〜5.7 万）。
  これは案①をそのまま PNG で使う分には見えない程度。
- **案①（線画ベタ塗り）**: 実寸（幅 50pt）でも鶴・桜と幕・月・傘の人物が一目で分かる。4 枚で線の太さ・塗りが揃っている。
  現行の図形描画とは別物で、「それっぽい花札」になった。
- **案②（ドット化）**: 56×84 なら読めるが、40×60 では小野道風の顔・傘の柄、月の朱の縁（赤い点に散る）、芒の穂が崩れる。
  札は 50pt 幅なので 1 ドット = 1pt 前後にしかならず、おじさん（48〜64 ドット高を 2pt/ドットで表示）ほどの
  ドット感は出せない。**ドット化は見た目の統一感より可読性を落とす**ので、採用するなら案①を推す。
  アプリの他の絵（SFC 級ドット絵のおじさん）と並ぶのはハブのタイルだけで、花札の画面内では札同士しか並ばない。
- **48 枚に進めるときの指示の直し**（今回の 4 枚で分かったこと）:
  - 「上端 15% に主役を置かない」を Codex が守らなかった（鶴の頭・傘の天辺・桜の枝が帯に食われる）。
    次は「上端 20% は地の色だけ（何も描かない）」と強く書くか、生成後に図案を下へ寄せる後処理を入れる。
  - 「幕の後ろにだけ桜」「月の縁の朱の輪」は守られたが、縁の輪はドット化で散るので、案①で行くなら問題なし。
  - 1 回の `codex exec` で 4 枚・約 5 分。48 枚は月ごと（4 枚ずつ）12 回に分けて、月の中で植物の描き方を揃えるよう
    「同じ月の 4 枚は同じ枝・同じ花の塊を使う」と指示する。
- 組み込み方（未決・会長 OK 後）: PNG を `Resources/` に 48 枚（1 枚 1024×1536 は過大。幅 256 前後に縮めて入れる）置き、
  `HanafudaCardFace` の Canvas 図案の代わりに `Image` を敷いて帯だけ従来どおり重ねる。帯・角丸・暗転・強調の
  コードはそのまま使える。

  帰属し（"you ... own the Output"）、商用利用の制限・表示義務は無い。アプリ内素材・ストアのスクショに使ってよい。
  注意: 既存の作品・商標に似た場合の責任は自分側。人が描いたと偽って表示しない。生成画像には C2PA / SynthID の来歴情報が入る。

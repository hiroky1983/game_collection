# おじさんのドット絵の作り方（3D 顔 → Codex で 2D → 自動ドット化）

2026-10-07 の試行で組んだ、おじさんキャラのドット絵を量産するスキーム一式をここに残す。

## 1. 結論と状態

3D の頭部一覧を正典にして Codex（画像生成）に衣装別の 2D ベタ塗り全身を描かせ、Claude 側のスクリプトで
自動的に 48 / 64 ドットへドット化する、という流れが今回試した方式の中で最良だった。

**採用は会長が保留中**。理由は Codex（OpenAI の画像生成）の契約を上げないと、量産するだけの利用量が
持たない見込みだから。このディレクトリは「今回のスキームを残しておく」という会長指示（2026-10-07）に基づく
記録で、採用決定ではない。

## 2. 手順

1. **顔の正典**: `refs/heads-3d.png`（4 方向 × 7 表情、3D。会長作成の参考画像）。顔・頭の形・髪・ひげ・耳・鼻は
   これに厳密に合わせる（同一人物に見えること）。
2. **Codex に 2D を描かせる**: `codex-spec-outfits.md`（Codex への仕様。絵柄・衣装・コマの指定）を渡して衣装別の
   2D ベタ塗り全身を生成する。コマンド例:

   ```bash
   codex exec --skip-git-repo-check --ephemeral -s workspace-write -C <dir> \
     -i refs/heads-3d.png -o last.md "<指示>" < /dev/null
   ```

   **`< /dev/null` が必須**。無いと標準入力待ちで無言で止まる（進んでいるように見えて実は停止している）。
   生成結果は `codex-outfits/a_work/`（作業服・腰痛おじさんパズル用）、`codex-outfits/b_kimono/`（和の着物・
   盆栽の合体パズル用）に 1 コマ 1 ファイルで保存し、`codex-outfits/sheet_a.png` / `sheet_b.png` に日本語ラベル付き
   一覧を作る（切り出し・一覧化は `codex-outfits/make_assets.py` を使用。このスクリプトは Codex 生成直後の
   一時ファイルを前提にしているため、そのままでは再実行できない参考コードとして置いている）。
3. **自動ドット化**: `outfit-pixel/make_outfit_pixel.py` で衣装ごとに固定パレット（20 色以内）の
   48 / 64 ドットへドット化する。手順は次の通り（`pixel-mock-puzzle/make_puzzle_pixel_mock.py` の手法を流用）。
   1. 白背景を枠からの塗りつぶしで透過にする（写り込んだ隣のコマの頭・効果線は連結成分の形で判定して除去）
   2. 5×5 のメディアンで画像生成のざらつきを均し、衣装ごとの固定パレットに減色
   3. 立ち絵（前）の高さが 48（64）ドットになる共通の縮尺で最頻色縮小（マスの中で一番多い色を採る。
      縁取り色は一定の割合以上で優先）
   4. 孤立ドット除去 → 孤立 1 ドットの多数決 → 輪郭を 1 ドットの縁取り色でそろえる
   5. `FIXUPS`（スクリプト内の定数）に書いた手直し（顔のドット単位の修正。場所と理由を記録）
   6. `px48/` `px64/` に各コマ PNG、`sheet_px.png` に比較一覧を出力

   実行:

   ```bash
   env -u NODE_OPTIONS /Users/yamadahiroki/opt/anaconda3/bin/python3 make_outfit_pixel.py
   ```

   （Pillow + numpy が必要。anaconda の scipy は numpy と不整合なので使わず、連結成分の検出は `pxlib.py` の
   自前 BFS で行っている）
4. **検証**: `outfit-pixel/verify.py` で色数・パレット外の色・半透明の有無を確認する（numpy が要るため
   anaconda の python3 で実行）。
5. **画面モック**: `outfit-pixel/make_mock_backpain.py`（腰痛おじさんパズル）、
   `outfit-pixel/make_mock_bonsai.py`（盆栽の合体パズル、コードはまだ無い企画用）で、ドット絵を実際の画面構成に
   置いたモックを作る（`mockkit.py` が共通部品。Pillow のみで numpy は不要なので `/usr/bin/python3` で動く）。

## 3. 結果の要点

- 48 ドットでも正面の顔は読める。横顔と、倒れるコマ（体が横長になる）は 64 ドットの方が良い。
- 作業服の紺（`U`）が縁取り色に近く、縁取りとの区別がドット化後にやや弱い。
- 元絵は頭頂が切れている構図のものがあり、ドット化後も頭頂が詰まって見える。

## 4. 比較した他の方式と失敗理由

いずれも今回の試行で先に試して不採用にしたもの。短くまとめる。

- **2D シートを直接自動変換**: Codex が描いた 3×3 のキャラクターシートをそのまま自動ドット化すると、顔がまだらに
  なった（アンチエイリアスや影の中間色がそのまま減色されず残り、ノイズ状のドットが出る）。
- **Codex に縮小までやらせた**: 「ドット絵に縮小して」と指示したら、Codex は「減色した」と報告したが、実際に
  開くと 500〜1000 色のままだった（虚偽報告ではなく確認不足だが、結果は同じで使えない）。
- **Codex にコードのドット単位で実装させた**: ドット座標を直接書くコードを書かせたところ、新規の絵を一切描かず
  既存のコマ（別キャラ）を流用しただけだった。
- **Codex に細かい仕様で頭部パーツを描かせた**: 「丸の直径 N ドット」のような規格は守るが、規格に収まる別の図形を
  描いただけで、同一人物に見えない（別人）結果になった。
- **Codex への一文指示**: 「おじさんのドット絵を描いて」のような一文だけだと、1 枚絵としては上手いが、ドット絵の
  規格（低解像度・固定パレット）を満たしておらず実際には 16 万色程度のフルカラー画像だった。

**教訓**: Codex の完了報告（「減色した」「ドット絵にした」等）は信用せず、成果物を開いて色数などの数字で
実際に確かめること。

## 1. ゲーム中の操作の洗い出し

「ゲーム中（局の進行中）にプレイヤーが使う操作」を、「⋯」の中と画面上の両方から拾った。
盤・札・牌のタップやスワイプ（進行そのもの）は 1 行にまとめ、ヘッダー右の **役の早見表 → ？（遊び方）→ 新規** は
全ゲーム共通（`Core/GameChrome.swift:176-208`）なので表から外した。決着後の「もう一回」「次のゲーム」も段の対象外として外した。

凡例: 場所の「⋯」= `GameOverflowBar` のメニュー / 「段」= 盤の下の画面上ボタン / 「幕」= 盤に重なるパネル・アラート。
広告の「無料 n→広告」= 無料 n 回のあとリワード広告。「毎回広告」= 無料枠なし。

### 1-e. 画面の縦構成（共通）

## 2. 全ゲームを同じ段にできるか（判断）

**結論: 23 本を 1 つの段には揃えられない。段が成立するのは 12 本で、残り 11 本は「段に置く操作が無い」か「進行の操作が段の位置を占めている」。**

| グループ | ゲーム | 段に入る操作（左から） | 判断 |
|---|---|---|---|
| ① 対局系 | 将棋・チェス・五目並べ・オセロ・囲碁 | 待った → （パス：囲碁のみ）→ ヒント（将棋・チェス・五目のみ）→ ⋯（投了） | **成立**。項目は 1〜2 個 + ⋯ |
| ② 一人用パズル・ソリティア系 | ソリティア・スパイダー・フリーセル・麻雀ソリティア・ナンプレ・マインスイーパー・神経衰弱 | 戻す → 助け（ヒント／ジョーカー／並べ替え／配る）→ 切り替え（メモ／旗／拡大）→ ⋯（自動で上がる・諦める・拡大） | **成立**。最大は麻雀ソリティア（3 個 + ⋯）。「拡大」は 5 本にあり、段に出すと場所を食うので「⋯」に残す前提 |
| ③ カード対戦系 | ポーカー・ブラックジャック・大富豪・花札・しりとり・四人打ち麻雀 | 無し（投了だけ） | **無理**。進行の操作（出す・パス・ヒット等）が段の位置を占める。合わせるなら「進行ボタンの行の高さ・角丸・⋯の見た目」だけ |
| ④ アクション・スワイプ系 | 2048・15パズル・ブロック崩し・チャリンコおじさん・柵越えおじさん | 一時停止だけ（2048・15 は無し） | **無理**。広告の入口（コンティニュー・途中から再開・広告を見てプレイ）は幕・ロビーにあり段には出せない |

**`reward_request` の回復という目的に対しては、①と②の 12 本で足りる**。広告が絡む「⋯」の項目（待った・ヒント・戻す・並べ替え・ジョーカー）はすべてこの 2 グループにあり、
③④の広告はもともと幕に出ていて v1.1.7 の「⋯」化の影響を受けていない。

## 3. 描き分けた案

共通の前提（全案）:

- 段の高さは **44pt + 上下 8pt = 60pt** で描いた。これは `GameOverflowBar` の既定値で、6 本では今と同じだが、
  **盤ゲーム 5 本（今 46pt）では 14pt、ナンプレ（52pt）では 8pt 高くなる**。余白を各ゲームの今の値に合わせれば
  盤は縮まない（44pt の枠は変わらないため）。SE でどれだけ盤が縮むかは実装時に実測する（オセロ・五目は
  `GameControlArea` が終局後の高さで予約しているので変わらない可能性が高く、将棋・チェスは #1689 で予約を外したので縮みうる）。
- 段は盤のすぐ下、余白は段と広告のあいだ（#1485 と同じ）。SE では余白が 8pt まで詰まる（破線で実測値を描いた）。
- 「⋯」は今の丸 44pt のまま右端。設定・遊び方はヘッダーの「？」に残す。

## 6. モックを作って分かったこと（判断材料）

- **段のボタンは今の「⋯」と同じ 44pt なので、上下の余白を今の各ゲームの値（盤ゲーム 1pt・ナンプレ 4pt・他 8pt）に揃えれば盤は縮まない**。
  モックは余白 8pt（60pt）で描いているため、将棋の SE では現状（00・46pt）より段が 14pt 高く、盤がその分縮んで見える（00 と 01 を比較）。
  余白をどこまで詰めるか（1pt だと段が盤と密着する）は実装時の論点。
- **SE で段に入るのは 2 個 + ⋯ まで**（案A）。3 個目を入れると「広告を見て」の 2 行目が縮む（07 の右）。麻雀ソリティアだけが 3 個必要で、ここをどうするか（並べ替えを「⋯」へ／案B の文字量）が決めどころ。
- **広告の入口が段に戻るのは 12 本**（①②）。③④の 11 本は段を作っても広告の入口は幕のままなので、`reward_request` の回復には寄与しない。
- **切り替え（メモ・旗・拡大）の見せ方が案を分ける**。案A はオンを紫の面 + チェックで表し、案B はアイコンの背を薄く塗るだけ。「拡大」は 5 本にあり、段に出すと 1 枠を常に食う。
- 大富豪の「⋯」は素の `Menu`（`ellipsis.circle`・`DaifugoView.swift:330-340`）で他ゲームの丸 44pt と見た目が違う。段を作らない③でも、ここだけは揃えられる。

社長の推奨（決定ではない）: **案A を基本に、SE の上限を「2 個 + ⋯」として麻雀ソリティアの「並べ替え」を「⋯」に残す**。
理由は、今の `GameButtonStyle.capsule` と `GameOverflowBar` をそのまま使えて実装が最小で済み、広告の有無を文字で読めるため。
案B は見た目が静かで良いが広告の印が小さく、`reward_request` を戻す目的に合いにくい。案C は目的には最も効くが「全ゲーム同じ大きさ」を崩す。

## 7. 作り方

```bash
cd docs/design/action-row
swiftc -O mock.swift -o /tmp/mockbin && /tmp/mockbin <出力ディレクトリ>   # PNG（@2x）
sips -s format jpeg -s formatOptions 75 --resampleWidth 1400 <PNG> --out <JPG>
```

macOS の `swiftc` 単体 + SwiftUI `ImageRenderer` で描いている。シミュレータもアプリのビルドも使わない。
盤・札・牌は段の見え方を比べるための簡略図で、本物の盤の描画コードは写していない。

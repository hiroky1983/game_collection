# 五目並べ CPU の段階表の再調整（#1566）

会長決裁（2026-09-29）で、隣り合う段の差を「上の段の得点率 60〜70%」に揃え直す記録。前回は `docs/analytics/gomoku-1463-ladder.md`。

## 条件

- 合否: 上の段の得点率 =（勝ち + 引き分け×0.5）÷ 全局数 が **60〜70% で合格**（70% 超・60% 未満は不合格）。
  1 組 400 局（開始局面 1〜200 × 先後入れ替え）。区間は「かんたん 対 入門」「ふつう 対 かんたん」の 2 つ
- 変えないもの: 考える時間（入門 0.3 / かんたん 0.5 / ふつう 1 / むずかしい 2 秒）、入門（1 手先・20%）、むずかしい（上限なし・100%）、
  損の幅 `slipMargin` 500、探索の形（各局面 14 手・四の延長）
- 変えてよいもの: かんたん・ふつうの「読む深さの上限」と「最善手を打つ確率」
- 計測: 前回 #1463 と同じ `Scripts/gomoku-cpu-bench`（最適化ビルド）`NPS=164954 CONCURRENCY=4`、開始局面は `CPUBenchLadder.opening`。
  今回 `match` に深さの差し替え（引数 7・8）を足した（`CPUBenchLadder.engine(maxDepth:)`）
- 計測機: クラウドの Linux・4 コア（前回と同じ種類）

### 制約から出る候補

- 深さ: 入門 ≤ かんたん ≤ ふつう、現在より深くしない（かんたん ≤ 3・ふつう ≤ 5）、隣との差 0〜1 手
  → **かんたん 1 か 2 手先**（入門 1 手先から 1 手まで）、**ふつう = かんたん か かんたん + 1**
- 確率: 30〜100%・10% 刻み、入門 ≤ かんたん ≤ ふつう ≤ むずかしい、隣との差 10〜40 ポイント
  → **かんたん 30〜60%**（入門 20% から）、**ふつう 60〜90%**（むずかしい 100% との差 10〜40）かつ かんたん + 10〜40
- 深さが同じ段どうしは確率に 10 ポイント以上の差 → 上の範囲で常に満たす
- むずかしいは深さ上限なしで「変えない」ため、ふつうとむずかしいの深さの差（0〜1 手）は当てはめていない（当てはめると満たせる値が無い）
- 現在のかんたん（3 手先・10%）は、確率の逆転（入門 20% > 10%）と深さの差（入門 1 → 3 で 2 手）の両方で制約外。ふつう（5 手先）も
  かんたんが 2 手先以下になるため 3 手先以下に下がる

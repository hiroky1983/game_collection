# 将棋: ヒントどおりに指し続けると「むずかしい」にどれだけ勝てるか（#1491）

会長依頼（2026-09-27）の条件で、毎手ヒントを使いヒントの手をそのまま指す側（以下「ヒント側」）と、
「むずかしい」の CPU を対局させた記録。

## アプリのヒントの実装（コードで確認したこと）

- ヒントは `ShogiGameModel.requestHint()` / `requestAdHint()` が `SimpleMinimaxEngine(level: BoardHintBudget.engineLevel)` で読む。
  `BoardHintBudget.engineLevel` は `CPUStrength.hard`（むずかしい）で、**対局中の段階（入門・かんたん・ふつう）を一切参照しない**。
  → ヒント側の手は段階に依らないので、**計測は 1 本**（段階別に測っても同じ対局になる）
- **アプリのヒントの考える時間は「むずかしい」と同じ 2.0 秒**で、依頼条件の「むずかしい + 0.5 秒」にはなっていない。
  ヒントのエンジンは むずかしい と設定が完全に同じ（深さ上限 `maxDepth` 32・最善手 100%（`.exact`）・定跡あり・時間 2.0 秒）
- 計測は依頼どおり **ヒント 2.5 秒**（むずかしい + 0.5 秒）で行う。アプリのコードは変えていない

## 条件

- `Scripts/shogi-cpu-bench`（最適化ビルドの単体バイナリ）の `hint` コマンド（今回追加）。`NPS=20000 PLIES=300 CONCURRENCY=4`（#1566 と同じ）
- 考える時間は局面数に置き換える: むずかしい 2.0 秒 = 40000 局面、ヒント 2.5 秒 = 50000 局面
- 開始局面は `CPUBenchLadder.opening`（6 手乱数・駒得の偏り歩 1 枚以内）。各開始局面でヒント側の先手・後手を 1 局ずつ
- 引き分け = 300 手の上限（千日手も含む。計測は千日手を判定しない）。勝率 =（勝ち + 引き分け×0.5）÷ 局数
- 両者とも最善手 100% で乱数を使わないので、同じ開始局面・同じ手番なら対局は再現する（多様性は開始局面だけから来る）
- ヒント回数の制限（無料 3 回 + 広告 5 回）は外し、ヒント側は毎手ヒントの手を指す

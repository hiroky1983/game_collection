# チェス CPU の段階表の再調整（#1566）

会長決裁（2026-09-29）に沿って、「かんたん」「ふつう」の **読む深さの上限** と **最善手を打つ確率** を測り直した記録。
前回 #1462（`docs/analytics/chess-1462-ladder.md`）の値だと、上の段が下の段に勝ちすぎていた（かんたん 対 入門 92.2%）。

## 条件

- 合否: 隣の段に対する上の段の得点率 =（勝ち + 引き分け×0.5）÷ 全局数 が **60〜70%**（70% 超も不合格）。1 組 400 局（開始局面 1〜200 × 先後）
- 変えるもの: かんたん・ふつう の深さの上限と確率だけ。考える時間・入門（0.02 秒・1 手先・60%）・むずかしい（2 秒・上限なし・100%）は据え置き
- 計測: `Scripts/chess-cpu-bench`（最適化ビルド）`NPS=100000 PLIES=300 CONCURRENCY=4`（#1462 と同じ）。考える時間は局面数（NPS × 秒）に置き換える。
  深さの差し替えのため `match` の段階名に `easy:1` のような深さの指定を足した（`CPUBenchLadder.engine(depth:)`）。外したときの損の幅 350 は据え置き
- 開始局面は全組で同じ 1〜200 番（組どうしを同じ局面で比べるため）

## 制約から残る組み合わせ

- 深さ: 現在より深くしない（かんたん ≤ 2・ふつう ≤ 3）、入門(1) ≤ かんたん ≤ ふつう、隣との差 0〜1 手 → かんたん 1 か 2、ふつう = かんたん か かんたん+1
- 確率: 30〜100%・10% 刻み、入門(60%) ≤ かんたん ≤ ふつう ≤ むずかしい(100%)、隣との差 10〜40 ポイント
  → かんたん 70〜80%（入門 +10 以上、かつ ふつうが むずかしい −10 = 90% 以下に収まる必要があるため 90% 以上は不可）、
  ふつう = かんたん +10〜+40 かつ 90% 以下
- むずかしいは深さの上限が無いので、ふつう 対 むずかしい の「深さ 0〜1 手」は当てはめようがない（むずかしいは据え置きの指示のため、確率の差だけを当てはめた）
- よって かんたんの候補は 4 通り（深さ 1・2 × 確率 70%・80%）、ふつうは かんたんごとに 2〜4 通り（計 12 通り）。全部測れる数なので絞っていない

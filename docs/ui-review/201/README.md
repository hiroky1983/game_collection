## 演出が実際に起きていることの裏取り

見た目の印象ではなく、コマの画素から測った。

**成り確認**（`01` の撮影と同じ実行・33コマ）

| 測ったもの | 結果 |
|---|---|
| 暗幕の濃さ（札から離れた点） | `(255,251,244)` → `(227,223,219)` へ**単調に**変化。t=7.39〜9.64 秒 = **2.25 秒**（指定 2.2 秒） |
| 札の横幅（文字を含まない行で計測） | 676px → 694px へ拡大 |
| 札の中心 | 拡大の間ずっと **602.5px から動かない**（= 縮小の基準が札の中心。盤の原点だと札が左上へ吸い込まれる #199） |

**手番バッジ**（`02` の撮影と同じ実行）

先手 `(74,59,51)`（= `Theme.fillStrong` `#4A3B33` そのもの）から
`(75,64,56)` → `(77,74,65)` → `(80,89,81)` → `(80,111,103)` → `(78,132,124)` →
後手 `(71,154,147)` へ単調に補間される。終端は着手から 2.2 秒後で、指定どおり。
`easeInOut` なので最初の 3 割ほどは変化が量子化で見えない。

## 既存の見た目を変えていないことの裏取り

base（`release/v1.1.3`）に**同じプローブを入れて別ビルド**し、同じ手順・同じインストール状態
（毎回 `uninstall` してから `install`）で撮った4状態を突き合わせた。

| 状態 | base との差 |
|---|---|
| 初期局面（静止） | **0 画素** |
| 2手進んだ静止盤面 | **0 画素** |
| 8八角を選んだ状態（着手先の丸＋2二角を囲む枠） | **0 画素** |
| 成り確認が出終わった状態 | **0 画素** |

出入りの**途中**だけが差分（= この PR で足した動きそのもの）。

## 操作のレスポンスが損なわれていないことの裏取り

**本実装の長さ（0.18 秒）のビルド**で成り確認が出る瞬間を 0.21 秒間隔で連写した。

| 状態変化からの経過 | 出終わった状態との差 |
|---|---|
| 最初のコマ（+0.27 秒以内） | 2.9%・**平均差 0.03**（目では区別できない） |
| 次のコマ（+0.70 秒以内） | **0 画素** |

演出そのものが 0.18 秒で、**連写の間隔（0.21 秒）より短い**。札が出るのを待たされる時間は
撮影の分解能に埋もれる。

## 実装のメモ

- 分岐（`if model.pendingPromotion != nil`）を呼び出し側の `.overlay { if … }` から
  `promotionOverlay` の**中**へ移した。アニメーションは**残り続ける親**（`ZStack`）に置かないと、
  消える側と一緒に修飾子も消えて `.transition` が効かない（#195 と同じ落とし穴）。
- 暗幕と札で**別の**トランジションを使う。ひとまとめに縮小を掛けると画面いっぱいの暗幕まで
  拡縮して、幕の縁が動いて見える。
- 分岐を層の中に入れたぶん、札を出していない間もこの層は盤の上に常設される。
  `allowsHitTesting(model.pendingPromotion != nil)` で素通しであることを明示した
  （空の `ZStack` は素通しだが、暗黙に頼ると中身を足したときに静かに盤のタップを塞ぐ）。
- 札の演出（0.18 秒）は**駒の移動（0.26 秒）より短く**取った。長いと、成った駒が動き出しても
  札がまだ被って残る。
- 手番バッジは色を決めている `sideToMove` を見張る。文字（先手番/後手番）は SwiftUI 側が
  クロスフェードする（`04` で実測）ので、指定は色の1か所だけでよい。

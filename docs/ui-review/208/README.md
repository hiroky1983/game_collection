# #208 神経衰弱の終局演出・手番表示 — 実測

`feat/concentration-result-turn-animation` の実測。撮影は iPhone 17 Pro / iOS 26.4（当番が起動した
シミュレータ。確認後に `simctl shutdown` 済み）、起動引数は
`-screenshotMode -startGame concentration`（広告は `NoopAdService` に差し替わる）。

シミュレータは自動タップができないため、**中断スナップショットを注入**して狙った局面から始めた。
CPU の手番から始まる盤にしておくと、`ConcentrationView.task(id:)` が起動して CPU が自動で
2枚めくるため、タップ無しで「ペア成立 → 終局」「ミスマッチ → 手番交代」の両方を撮れる。

演出そのものは実長では 0.2〜0.6 秒で、スクリーンショットの間隔（約 0.23〜0.31 秒）では
1コマも中間状態を拾えない。そのため**長さを引き伸ばしたプローブビルド**で撮っている。
**プローブの変更はコミットに含めていない**（この PR に入っているのは画像2枚とこの README のみ）。

| 画像 | 内容 | プローブでの長さ | 製品の長さ |
|---|---|---|---|
| `result-overlay-fade.jpg` | 終局オーバーレイの出現 | 待ち 2.5 秒・フェード 3.0 秒 | 待ち 0.35 秒・フェード 0.25 秒 |
| `turn-highlight.jpg` | 手番のアクティブ表示の入れ替え | 2.5 秒 | 0.2 秒 |

長さと無関係な部分（トーンの大小関係・View への結線）は `ConcentrationMotionTests` が固定する。

## `result-overlay-fade.jpg`（受け入れ条件1）

| コマ | 状態 |
|---|---|
| 1 | 対局中。CPU の手番（右のチップがコーラル）で、🥝 が1枚めくれている途中 |
| 2 | **最後のペアが成立した直後。まだ暗幕は降りていない**（待ちの区間） |
| 3 | フェード中。**結果カードが半透明で、後ろの盤が透けて見えている** |
| 4 | フェード完了 |

コマ2が待ちを入れた理由そのもので、`isGameOver` は最後のペア成立と**同じ更新**で真になる
（`ConcentrationModel.checkGameOver`）。待ちが無いと、めくりの 0.35 秒の途中で暗幕が降りて
「どの2枚で終わったのか」が見えないまま結果だけが出る。

暗幕の進行は画素サンプリングでも裏取りした。盤の左上（暗幕は掛かるが結果カードは載らない領域）の
輝度を約 0.31 秒間隔で追うと、プローブでは 237 のまま 11 コマ（≒3.4 秒 = 待ち 2.5 秒 + めくりの
バネの収束）動かず、そのあと 9 コマかけて 237 → 149 へ落ちて底打ちした（≒2.8 秒。プローブの
フェード 3.0 秒に一致）。製品の長さで撮り直すと、同じ輝度が 237 → **160（1コマだけ中間）** → 148
となり、待ちとフェードの合計が撮影間隔 2 コマ分（≒0.6 秒 = 0.35 + 0.25）に収まることを確認した。

## `turn-highlight.jpg`（受け入れ条件2）

| コマ | 状態 |
|---|---|
| 1 | CPU の手番。右の `CPU` チップがコーラルで塗られている |
| 2 | 切り替え開始。左の `あなた` に薄くティールが乗り、右のコーラルが抜け始める |
| 3 | 切り替え中。**両方が中間色**（クロスフェードしている） |
| 4 | あなたの手番。左がティール・右が無地に落ち着いた |

チップの背景 Capsule と文字色（白 ↔ `Theme.inkSub` / `Theme.ink`）はどちらも同じ `isActive` で
決まるため、`.gameAnimation(_:value: isActive)` 1つで一緒に馴染む。

こちらも画素サンプリングで裏取り済み。`あなた` チップの中心は
(234,232,231) → **(70,205,200)**、`CPU` チップは (255,154,144) → (240,238,237) へ、
11 コマ（≒2.5 秒 = プローブの `turnHighlightDuration`）かけて入れ替わった。

コマ3で「あなた」の文字が読みにくいのは、白文字がティールの中間色の上に乗る一瞬があるため。
製品の 0.2 秒ではこの状態は1フレーム未満で、静止して読む場面にはならない。

## 演出のトーン（受け入れ条件3）

長さを `ConcentrationMotion` に集め、**手番の切り替え 0.2 秒 < 終局のフェード 0.25 秒 ≦
カードめくり 0.35 秒**の順に固定した（大小関係は `ConcentrationMotionTests` が押さえる）。
1ゲームに何十回も起きる手番の入れ替えほど軽く、1度きりの終局とゲームの主役であるめくりほど
濃い、という並びで、既存のめくり（`spring(response: 0.35, dampingFraction: 0.75)`）は
値を変えずに定数へ寄せただけ。終局のフェード 0.25 秒はオセロ（#205）と同じ値にしてある。

## 決着の瞬間にレイアウトを動かさないこと

`.gameAnimation` は**オーバーレイの ZStack にだけ**置いている。`model.isGameOver` は
「待った」欄の消滅と `RecommendationSlot(isFinished:)` の切り替えも同時に起こすため、
外側（VStack）に置くとそれらまで animate されて決着の瞬間に盤が伸び縮みする。
コマ1→2 で「待った」欄が瞬時に消えているのが、その入れ替えを従来どおり即時に留めた結果。
オセロ #205 が同じ理由で `.gameAnimation(.none, value:)` を外側に置いているのと対になる扱い。

## Reduce Motion

フェード・手番の切り替え・めくりはいずれも `gameAnimation(_:value:)` 経由なので、ON のときは
補間が起きず即時反映になる（#210 の共通レイヤー）。素の `.animation(` を使っていないことは
`ConcentrationMotionTests` と Core の横断テスト（`MotionTests`）の両方が見ている。

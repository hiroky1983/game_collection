# #206 ポーカーのショーダウン・ポット表示の演出 — 実測

`feat/poker-showdown-animation-206` の実測。撮影は iPhone 17 Pro / iOS 26.4（当番が起動した
シミュレータ。確認後に `simctl shutdown` 済み）、起動引数は
`-screenshotMode -startGame poker`（広告は `NoopAdService` に差し替わる）。

シミュレータは自動タップができないため、ショーダウンまで進める操作は**撮影用のプローブビルド**
（`-pokerShowdownProbe` で自動的に配牌 → 公開まで進める + 演出の長さを引き伸ばしたもの）で作った。
**プローブの変更はコミットに含めていない**（この PR に入っているのは画像2枚とこの README のみ）。

| 画像 | 内容 | プローブでの長さ | 製品の長さ |
|---|---|---|---|
| `showdown-flip.jpg` | CPU 手札の公開（反転） | 1枚 12 秒・段差 2.5 秒 | 1枚 0.3 秒・段差 0.07 秒 |
| `pot-numeric.jpg` | ポットの枚数の入れ替え | 4 秒 | 0.24 秒 |

実長ではスクリーンショットの間隔（約 0.2 秒）に対しても演出が短く、5 枚の段差を1コマずつ
切り出せないため引き伸ばしている。翻訳そのもの（進捗 → 見える面・回転角）は
`PokerMotion` の純関数で、長さと無関係に `PokerMotionTests` が固定している。

## `showdown-flip.jpg`（受け入れ条件1）

| コマ | 状態 |
|---|---|
| 1 | 公開前。5 枚とも裏（青） |
| 2 | 1枚目が Y 軸まわりに回り始め、裏面が斜めに細くなる |
| 3 | 1枚目が真横に近づき、**2枚目が遅れて回り始める**（段差） |
| 4 | 1〜4枚目は表、5枚目が真横（`6♠` が細く見えている） |
| 5 | 公開後。5 枚とも表で、**数字・スートが鏡像になっていない** |

コマ4だけは別の撮影回（同じプローブ設定・別の配牌）で、5枚が別々の進捗にある瞬間が
1コマに収まったもの。他の4コマは同一の撮影回の連続フレーム。

段差は画素サンプリングでも裏取りした。CPU の各カード列の「青（裏面）の占有率」を
0.2 秒間隔で追うと、1枚目が 98% → 40% と細くなっていく間、2〜5枚目は 99% のまま動かず、
**2枚目が動き始めるのは1枚目の約 2.4 秒後**（プローブの段差 2.5 秒に一致）だった。

## `pot-numeric.jpg`（受け入れ条件2）

| コマ | 状態 |
|---|---|
| 1〜3 | アンティが積まれて 0 → 20 枚。桁が転がっている途中（数字が中間の形） |
| 4 | 転がり終わり `20枚` |
| 5 | 決着でポットが勝者に渡り `0枚` へ戻ったところ |

## 演出のトーン（受け入れ条件3）

もとは山場（ショーダウン）に演出が無く、交換カードの選択にだけバネが付いていて濃淡が
逆転していた。長さを `PokerMotion` に集め、**手札の選択 0.25 秒 ≦ ポット 0.24 秒 <
ショーダウン全体 0.58 秒**の順に固定した（大小関係は `PokerMotionTests` が押さえる）。

## 撮影中に見つけて直したこと

ポットの数値に `.contentTransition` + アニメーションを付けると、**枚数が変わるのと同時に画面
全体のレイアウトも動く場面**（ゲーム画面へ入りながらアンティが積まれる等）で、その `Text` だけが
古い位置から滑ってきて **CPU の手札の上に「20枚」が浮く**。プローブの1回目で実際に撮れたため、
`.geometryGroup()` を足して位置は親と一体で決まるようにし、数字の入れ替えだけを演出に残した。
`PokerMotionTests` の結線テストで `.geometryGroup()` の有無も見ている。

## Reduce Motion

反転・数値の入れ替えはどちらも `gameAnimation(_:value:)` 経由なので、ON のときは補間が起きず
即時反映になる（#210 の共通レイヤー）。素の `.animation(` を使っていないことは
`PokerMotionTests` と Core の横断テストの両方が見ている。

## 対局中の盤が小さくなる件（iPhone SE のみ・実測値と理由）

レコメンドカード（56pt）+ 行間 8pt = **64pt を常に確保する**のがこの修正の要。
カードは出るとは限らず×でも閉じられるため、条件付きで高さを足すやり方では安定しない
（#139 で `RecommendationCard.heightPlaceholder` を Core に用意した理由）。

確保したぶんは**駒・牌・カード・文字の大きさ（＝タップ目標）を一切変えずに縦の余白から
捻出した**（`VStack` の間隔 10→8 / 20→14、ステータスバーの上下余白 8〜12→6〜10、
五目並べの石情報行の最小高 36→30、下端の `Spacer(minLength:)` 8→0）。
それでも足りないぶんが iPhone SE での 12〜47pt にあたる。

- **麻雀ソリティアの牌は 1pt も小さくなっていない**。牌の大きさは横幅で決まるため
  （`min(幅/15.56, 高さ/11.98)` の前者が常に小さい）、盤面領域の高さが減っても影響しない。
  実測でも牌の並びの横幅は修正前後で同一（iPhone 17: 390.7pt / SE: 364.0pt）。
- 残る 4 画面は「対局中に最大 47pt 小さい代わりに、決着の瞬間に 42〜112pt 縮まない」という
  交換になっている。#139 の将棋（対局中 334→321pt）と同じ判断。

## 再現方法

シミュレータの**データコンテナ配下**に中断スナップショットを書き込み、`-startGame <id>` で起動する。

```sh
BUNDLE_ID=com.hirockysan1983.asobiba
DATA="$(xcrun simctl get_app_container booted "$BUNDLE_ID" data)"
mkdir -p "$DATA/Library/Application Support/Snapshots"
# "$DATA/Library/Application Support/Snapshots/<gameID>.json" にスナップショットを書く
xcrun simctl launch booted "$BUNDLE_ID" -startGame gomoku -simulateRecommendation shogi
```

- 決着後の状態は、スナップショットに終局を書いて復元させる
  （五目並べ・オセロ = `winner`、2048 = 詰みの盤面、麻雀ソリティア = `faces` が全て `null`）。
- **マインスイーパーだけは復元では終局にできない**（`MinesweeperModel.init` が常に `.playing`）。
  この画面用に DEBUG 限定の起動引数 `-simulateGiveUp`（= 「諦める」と同じ経路）を足してある。
- レコメンドカードは `-simulateRecommendation <gameID>`（DEBUG 限定）で条件を通さずに出せる。
- 初回だけ出る遊び方ヒントの 1 行が入ると盤の高さが変わるため、撮影前に各ゲームを
  2 回空打ちして「見せた」を消費しておく。

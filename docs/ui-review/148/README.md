# #148 終局後に盤面が縮む — 画面確認（五目並べ・マインスイーパー・麻雀ソリティア・オセロ・2048）

`#139`（将棋）で入れた手当ての横展開。盤（またはカードグリッド）は**塗り色の外接矩形を
ピクセル単位で実測**し、一辺の長さで比較している。麻雀ソリティアだけは終局時に盤面が
「取り切った演出」に差し替わるため、盤の一辺ではなく**盤面領域の高さ**
（ステータスバーの下端〜操作カードの上端）を測っている。

**数値の出し方**: pt = 実測ピクセル ÷ 画面の倍率（iPhone 17 は 3、iPhone SE は 2）。
差と割合は**丸める前の pt から計算し、結果を小数第 1 位で四捨五入**している
（表の値どうしを引き算しても丸め誤差の範囲で一致する）。

## gomoku-record-label.jpg — 五目並べで記録ラベルと手数が同居することの確認

ステータスバーへ寄せた結果、終局後の 1 行に「結果 / 通算成績 / 手数」が並ぶ。
将棋（`#139`）は手数を検討ナビの「n/N手」に譲れたが、五目並べには代わりの表示が無いため
**手数はステータスバーに残したまま記録を足している**。狭い iPhone SE でも重ならず収まり、
盤の一辺も変わらない（iPhone 17: 370.0pt / SE: 260.0pt）。

この状態は、CPU（白）が 4 連の局面で手番を持つスナップショットを復元して**実際に CPU に
勝たせて**作っている（`gameDidFinish` を通るので記録ラベルが本物の値になる）。

## 対局中の盤が小さくなる件（実測値と理由）

レコメンドカード（56pt）+ 行間 8pt = **64pt を常に確保する**のがこの修正の要。
カードは出るとは限らず×でも閉じられるため、条件付きで高さを足すやり方では安定しない
（`#139` で `RecommendationCard.heightPlaceholder` を Core に用意した理由）。

確保したぶんは**駒・牌・カード・文字の大きさ（＝タップ目標）を一切変えずに縦の余白から
捻出した**（`VStack` の間隔 10→8 / 20→14、ステータスバーの上下余白 8〜12→6〜10、
五目並べの石情報行の最小高 36→30、下端の `Spacer(minLength:)` 8→0）。
それでも足りないぶんが下表の減少にあたる。

| ゲーム | iPhone 17 | iPhone SE 3rd |
|---|---|---|
| 五目並べ | 0.0pt | **-33.0pt** |
| マインスイーパー | 0.0pt | **-13.0pt** |
| 麻雀ソリティア（盤面領域の高さ） | **-47.0pt** | **-47.0pt** |
| オセロ | 0.0pt | **-39.0pt** |
| 2048 | 0.0pt | **-14.5pt** |

- **麻雀ソリティアの牌は 1pt も小さくなっていない**。牌の大きさは横幅で決まるため
  （`min(幅/15.56, 高さ/11.98)` の前者が常に小さい）、盤面領域の高さが 47pt 減っても
  影響しない。実測でも牌の並びの横幅は修正前後で同一（iPhone 17: 390.7pt / SE: 364.0pt）。
  上表の -47.0pt は牌の下に空く余白が減ったぶん。
- 残る 4 画面は iPhone SE でのみ 13.0〜39.0pt 小さくなる。「対局中に最大 39pt 小さい代わりに、
  決着の瞬間に 42.5〜106.0pt 縮まない」という交換で、`#139` の将棋（対局中 334→321pt）と同じ判断。

## 再現方法

シミュレータの**データコンテナ配下**に中断スナップショットを書き込み、`-startGame <id>` で起動する。

```sh
BUNDLE_ID=com.hirockysan1983.asobiba
DATA="$(xcrun simctl get_app_container booted "$BUNDLE_ID" data)"
mkdir -p "$DATA/Library/Application Support/Snapshots"
# "$DATA/Library/Application Support/Snapshots/<gameID>.json" にスナップショットを書く
xcrun simctl launch booted "$BUNDLE_ID" -startGame gomoku -simulateRecommendation shogi
```

- 決着後の状態は、スナップショットに終局を書いて復元させる
  （五目並べ・オセロ = `winner`、2048 = 詰みの盤面、麻雀ソリティア = `faces` が全て `null`）。
- **マインスイーパーだけは復元では終局にできない**（`MinesweeperModel.init` が常に `.playing`）。
  この画面用に DEBUG 限定の起動引数 `-simulateGiveUp`（= 「諦める」と同じ経路）を足してある。
  `giveUp()` は `.playing` でないと効かないため、**中断スナップショットと併せて使う**こと。
- レコメンドカードは `-simulateRecommendation <gameID>`（DEBUG 限定）で条件を通さずに出せる。
- 初回だけ出る遊び方ヒントの 1 行が入ると盤の高さが変わるため、撮影前に各ゲームを
  2 回空打ちして「見せた」を消費しておく。

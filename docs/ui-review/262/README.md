# #262 数独の復活 — 画面確認

`feat/sudoku-revival` の実測。撮影は `-screenshotMode -startGame sudoku`（広告は `NoopAdService` に
差し替わるのでバナー枠は空。高さ 50pt は `BannerSlot` が常に確保する）。

盤面は**実際の生成エンジン**（`SudokuEngine.generate(difficulty: .normal, using:)`・種 20260825）で作った
出題を中断スナップショットとして注入し、そこから復元させたもの。撮影用に盤を手で書いてはいない。
シミュレータは自動タップができないため、途中まで解いた状態はこの経路でしか作れない。

## 確認できること

### レイアウト

- **いちばん狭い iPhone SE 第3世代でも、ステータスバー・盤・数字パッド・操作バー・バナー枠が
  重なりなく縦に収まる**。盤は `aspectRatio(1, .fit)` + `layoutPriority(1)` で、余った高さを取る。
- **決着しても盤の大きさが変わらない**。`controlArea` がプレイ中（数字パッド + 操作バー）と
  終局後（記録 + レコメンド）の高さを ZStack のひな形で揃えているため（#148 と同じ手当て）。
  `playing.jpg` と `states-se.jpg` 右端で盤の下端が同じ位置にあることで確認できる。

### 色分け（4 状態が 1 枚に写っている）

| 見た目 | 意味 |
|---|---|
| 濃い茶（`Theme.ink`）の太字 | 出題として最初から入っていた数字 |
| ティール（`Theme.teal`） | プレイヤーが自力で入れた数字 |
| 紫（`Theme.purple`） | ヒントで埋めたマス（上段の 4 と 5） |
| コーラルの面 + コーラル文字 | 正解と違う数字（4 行 2 列の 5） |
| 灰色の小さな数字 | メモ（1・5・8） |

終局後（`states-se.jpg` 右）は、諦めて表示した答えを `Theme.inkSub` に落としてある。
自力で入れた数字と同じ色にすると「自分で解いた盤」と見分けが付かないため。

### ダークモード（#187）

地・面・文字だけが反転し、差し色（ヒントの紫・誤りのコーラル・自力入力のティール）は
両モードで同じ値。3×3 の太線は `Theme.ink` なのでダークでは明色に反転して残る。

## タップ標的（#262 受け入れ条件）

**9 列 × 44pt = 396pt は、iPhone SE 第3世代の内容幅 343pt にも iPhone 17 Pro の 370pt にも入らない**
（左右 16pt ずつの `Theme.pad` を引いた値）。等倍で画面幅に収める描き方のままでは、どの iPhone でも
グリッドのマスを 44pt にできない。したがって**マインスイーパー（#203）と同じく拡大モードを用意し、
そちらで 44pt を満たす**方式を採った。

| 対象 | 値 | 備考 |
|---|---|---|
| 数字パッドのボタン（iPhone SE） | **63.8 × 44pt 以上** | 5 列 × 2 段。10 個を 1 段に並べると 28.9pt になり HIG を割る |
| 操作バーのボタン（メモ / ヒント / 諦める） | **高さ 44pt** | `minHeight: SudokuMetrics.padButtonMinSide` |
| 拡大トグル | **44 × 44pt** | `contentShape(Rectangle())` で角も取りこぼさない |
| 盤のマス（拡大モード） | **44 × 44pt** | `SudokuMetrics.zoomedCellSide` |
| 盤のマス（等倍・iPhone SE） | **38.1pt** | 9×9 を一望できることを優先した既定表示 |

これらの数値は `SudokuMetricsTests` で固定してある（定数だけでなく、View がその定数を
実際に `frame` へ渡していることもソース走査で検証している）。拡大モードそのものは
トグルのタップが要るため、シミュレータの静止画では撮れていない（自動タップができないため）。

## 既存の見た目を変えていないことの裏取り

駒をマスの中からマスの上の層へ移したため、「静止しているときの見た目が変わっていない」ことを
**base（`release/v1.1.3`）を別ビルドしてピクセル比較**で確認した。両ビルドに同じプローブを入れ、
同じ操作を同じタイミングで再生して撮った 33 コマを突き合わせている。

| 状態 | base との差 |
|---|---|
| 対局開始直後の静止した盤面 | **0 画素** |
| 駒を選んだ状態（黄色のマス＋着手先の丸） | **0 画素** |
| 着手後の静止した盤面（1手目・3手目） | **0 画素** |
| 8八角を選んだ状態（丸4つ＋3三の枠） | **0 画素** |
| 着手アニメーションの最中 | 0.20%（＝この PR で足した動きそのもの） |

比較範囲は盤面のみ（ステータス行の「直前 …」や手数は CPU の指し手で当然変わるため除外）。
`base` 側にだけ存在するコマ・`after` 側にだけ存在するコマが出ないよう、
各コマについて相手側の最も近いコマを探して突き合わせている。

## 実装のメモ

- 駒の同一性を**マスに紐づけない**のがこの Issue の本体。前の配置と新しい局面を突き合わせて
  「動いた駒には同じ ID を渡す」対応付け（`ShogiPieceLayout`）を作り、SwiftUI が座標を補間できるようにした。
  局面の差分しか見ないので、人間の着手・CPU の着手・成り・駒取り・打ち駒・待った・検討ナビの
  前後移動が**すべて同じ 1 経路**を通る。
- 着手先の印は駒より**上**に重ねている（`targetLayer`）。マスの中に描いていた頃の重なり順を保つため。
  逆にすると取れる駒を囲む枠が駒の下に潜る。
- マス 1 つぶんの間隔は盤の実寸 ÷ 9 から取っており、`ShogiCell` 側の余白の積み上げを数式で
  再現していない。マスの組み方を変えても駒の位置がずれない。

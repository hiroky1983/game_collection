# #195 大富豪: カードの状態変化のアニメーションとタップ操作のフィードバック — 画面確認

撮影環境: **iPhone SE 第3世代（375×667pt・@2x）** と iPhone 17 Pro Max（440×956pt・@3x）・
Debug ビルド・`-screenshotMode`（広告を出さず ATT も聞かない）。
SE を主にしているのは、**タップ標的の 44pt を最初に割るのが対応端末の中で最も狭い 375pt** だから。

**撮り方**: シミュレータはタップ操作を自動化できないため、大富豪の中断スナップショット
（2ゲーム目・場に ♣4・人間の手番・手札13枚）をアプリのコンテナへ注入し、`-startGame daifugo`
でその画面を直接開いている。タップが要る状態（押下中・実際に札を出す動き）は、
**コミットしない使い捨てのプローブビルド**で撮影した（内容は各節に明記。撮影後に `git restore` 済み）。

## 01-before-after.jpg — 変更前後（iPhone SE・375pt）

同じスナップショットを `release/v1.1.2` の HEAD と本 PR でそれぞれビルドして撮った。

**見た目はほぼ変わらない**のが意図した結果。手札の列間隔を 4pt → 0pt にした代わりに
1列あたりの幅が 42.1pt → 45.6pt に広がるため、カード間の隙間は 4.1pt → 3.6pt とほぼ同じに収まる
（カードの描画サイズ 42×60pt は変えていない）。

## 02-tap-and-press.jpg — タップ標的と押下フィードバック

| 面 | 内容 |
|---|---|
| 左 | **タップ判定の可視化**（プローブ: タップ領域に `Color.red.opacity(0.28)` を敷いたビルド） |
| 中 | 通常時（製品コードそのまま） |
| 右 | **押下中**（プローブ: `PopButtonStyle` の `isPressed` を常に真にしたビルド） |

- 左の赤い帯が**隣の列と隙間なく連続している**のが、判定を列いっぱいに広げた結果。
  この画像（750×1334px = @2x）を実測すると **1列 91.0px = 45.5pt** で、HIG の 44pt を満たす。
  従来は判定がカード幅の 42pt に張り付いていたため、7列グリッドで誤タップを誘発しやすかった。
- 右の「パス」「カードを選ぶ」は通常時より**わずかに縮んで（0.96 倍）薄く（0.85）**なっている。
  従来は `.buttonStyle(.plain)` で押下時の変化が一切なかった。

計算そのものは `DaifugoHandLayoutTests` で 375 / 393 / 430pt について固定してある
（列間隔を 4pt に戻すと 42.14pt となって落ちることを実測で確認済み）。

## 03-animation.jpg — 場と手札のアニメーション

プローブ（起動3秒後に出せる札を1枚選んで自動で出す）で画面収録し、
**60fps・0.20秒ぶん = 12コマ**を左上→右下の順に並べたもの。

- **上段（場）**: ♣4 が縮みながら薄くなって消え、♠5 が小さい状態から拡大しつつ現れる
  （`.transition(.scale.combined(with: .opacity))` + 0.18秒の `easeInOut`）。従来は瞬間的に差し替わっていた。
- **下段（手札）**: 出した ♠5 が縮んで消え、**後ろの札が左へ詰めながら動く**
  （2段目の 10♦ が1段目の末尾へ移動していく様子が見える）。従来は瞬時に詰まっていた。
- リザルトへの切り替え（`.playing` → `.result`）も同じ仕組みで 0.2秒のフェードにしている。

すべて Reduce Motion 追従の共通レイヤー（`gameAnimation` / #210）経由で書いているため、
「視差効果を減らす」を ON にした端末ではアニメーションだけが落ち、状態変更はそのまま反映される。
素の `withAnimation` / `.animation(` が混ざっていないことは `MotionTests` のガードで担保している。

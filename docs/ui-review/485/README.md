# #485 iPad の縦の余白（ハブ・ポーカー）

`iPad Pro 13-inch (M5)`（2064×2752）と `iPhone 17 Pro Max`（1320×2868）で撮影。
ビルドはどちらも Debug・`-screenshotMode`。

撮影スクリプトは **`main` の `Scripts/capture-aso-screenshots.sh`（18 画面版・`ff5f5be`）**を
この release ブランチのツリーへ一時的に持ち込んで実行した（同スクリプト自身が「まだ公開して
いない版のツリーで実行する前提」と書いているとおり）。`release/v1.1.3` 側のスクリプトは
10 画面・8 ゲームのままで、`docs/aso/screenshots/ipad/` の現行 18 枚とファイル名が合わないため。

## 実測（下端から続く「地の色だけの行」の割合）

| 画面 | before（`6144a06`） | after |
|---|---|---|
| `01-hub` | 53.1%（1460px / 2752px） | **7.1%**（196px） |
| `16-poker` | 47.2%（1300px） | **7.6%**（208px） |
| `18-settings` | 22.3% | 7.2%（設定シートの背後にハブが写るため連動して改善） |
| 残り 15 枚 | — | 変化なし |

測り方は Issue 本文と同じ定義で、**分子・分母とも画面の全 2752 行**（例: `01-hub` の before は
1460 / 2752 = 53.1%）。ディスプレイの角丸とホームインジケータは UI の部品ではないので、
**その行が「地の色だけか」を判定するときに該当する画素を見ない**ようにしている
（左右 60px を常に、最下部 40 行では中央 40% を無視）。**行そのものを数えから外してはいない**ので、
除外した画素ぶん分母が減るということはない。**この定義で Issue の実測値（52.7% / 44.8%）が
再現できることを先に確かめてから使っている。**

## iPhone が動いていないことの裏取り

base（`6144a06`）を別ワークツリーでビルドし、**同じシミュレータでアプリを uninstall してから**
10 枚ずつ撮って比較した（install 状態を揃えないと初回ガイドの有無で差が出る）。

- 10 枚中 9 枚が**ピクセル差 0**
- 残る `10-settings` は 70px（0.002%・「完了」ボタンのすりガラスのアンチエイリアス）。
  拡大して目視でも差は見えない

## 変更していない 15 枚が本当に変わっていないことの裏取り

`main` にコミット済みの 18 枚と、この修正で撮り直した 18 枚を比較すると、
**変えていない 15 枚の差はすべて 1135px・bbox (175,20)-(268,47)** に収まる。
これはステータスバーの**日付**（`9月7日(月)` → `9月8日(火)`）だけで、画面の中身は 1px も動いていない。
撮影環境が入稿物の撮影環境をそのまま再現できていることの確認でもある。

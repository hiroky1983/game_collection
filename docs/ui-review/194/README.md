# #194 大富豪: 投了・やり直しの導線 — 画面確認

撮影環境: iPhone 17 Pro Max（430×932pt・iOS 26.4）・Debug ビルド・`-screenshotMode`
（広告を出さず ATT も聞かない。シミュレータは AdMob 側でテストデバイス扱いになるため、
Release でもバナーに `Test mode` の帯が写り込む）。

**撮り方**: シミュレータはタップ操作を自動化できないため、大富豪の中断スナップショット
（2ゲーム目・場に ♣4・人間の手番・手札5枚）をアプリのコンテナへ注入し、`-startGame daifugo`
でその画面を直接開いている。確認ダイアログとリザルトはタップが要るので、**その状態を初期値に
した使い捨てのプローブビルド**（`showResignConfirm = true` / 起動直後に `resign()` を呼ぶ）で
撮影した。プローブの変更はコミットしていない。

## before-after-toolbar.jpg — ツールバーの差分

| | 修正前 | 修正後 |
|---|---|---|
| ツールバー | 「戻る」と `?` のみ | **「投了」を追加**（`.primaryAction`） |
| 対局中以外 | — | 決着後・上がった後は `disabled`（灰色） |

盤面・手札・操作ボタンの配置は変えていない（左右のスクリーンショットでツールバー以外は同一）。

他ゲームのツールバーはアイコンのみだが、旗アイコン単体では「投了」と読めないため文字を出している。
iOS 26 のツールバーは `Label` を渡すとアイコンだけに畳むので（`.labelStyle(.titleAndIcon)` も効かない）、
`Text` を直接渡している。

## resign-flow.jpg — 投了の確認と結果

- **確認ダイアログ**: 「投了しますか？」/「投了する」（destructive・赤）。本文で
  「今のゲームを打ち切ります。あなたは大貧民になり、負けとして記録されます。」と結果を先に伝える。
  ツールバー起点なので iOS 26 ではポップオーバーとして出る（枠外タップでキャンセル）。
- **投了後**: 「あなたは 大貧民」＋**投了**バッジ。順位表は CPU1（残り4枚）→ CPU3（残り5枚）→
  CPU2（残り6枚）→ あなた の順で、**残った CPU は手札の少ない順**に並んでいる。
  「通算 0勝1敗」の 1敗 が、投了が敗北として記録されたことの実機側の裏取り。
- 決着後はツールバーの「投了」が灰色（`canResign == false`）になり、操作は「次のゲーム」に移る。

# ゲーム別のヒント仕様

`docs/spec-app.md` から分離した（#2194。内容の変更なし）。ヒントの共通部品は `BoardHintBudget`。

#### 戦略ゲームのヒント（`BoardHintBudget`・#1118・#1500・v1.1.6 / v1.1.7）

将棋・チェス・五目並べ・オセロの 4 本が持つ**回数制のヒント**。v1.1.6 で入れたときは無料 3 回のみだったが（会長決裁
2026-09-19「無料 3 回のみ・広告連携なし」）、**`release/v1.1.7` の #1500 で広告での補充を足した**
（会長決裁 2026-09-27。前の決裁はこの Issue で上書きされた）。
オセロは #2011（`release/v1.1.11`・会長決裁 2026-10-10）で同じ仕組みに載せた。
**囲碁も #2027（`release/v1.1.11`・会長決裁 2026-10-11）で同じ仕組みに載せた**（5 本目）。「⋯」メニューのヒントで、`GoEngine(level: .hard)`
（8,000 回・2 秒。+0.5 秒の上乗せはしない）が読んだ最善手の交点を紫の輪で示す。**最善手がパスのときは印を置く交点が無いので、
盤上の帯「ここはパスでよい局面です」で示し VoiceOver にも読ませる**。読みは `withAITurnGuard` に載り、読みの最中の着手・パス・待った・
新規対局・投了では印を出さず回数も減らさない（#1903）。使った回数は `GoSnapshot.hintsUsed`（Optional）、決着は `hints.winLossScore`。
**15パズルも #1975（`release/v1.1.11`・会長決裁 2026-10-11）で同じ `BoardHintBudget`（無料 3 回 + 広告で最大 5 回）に載せた**が、
盤ゲームではないので「⋯」ではなく**盤の下の操作の段**にヒントのカプセル 1 つ（「あと N 回」/「0回 ▶ 広告を見て +1」）を置く。
押すと「次に動かす 1 枚」を紫の枠（`BoardGameHintColor`）で示す。示す手は重み付き A\*（マンハッタン距離 + 線形競合・
`FifteenHintSolver`）が返す「揃うまでの 1 本の道の最初の 1 手」で、示す通りに動かし続ければ必ず揃う。展開数に上限を置いた同期探索
（メインスレッド）。使った回数は `FifteenSnapshot.hintsUsed`（Optional）に持ち回り、使った局は順位表に送らない。
広告は押下起点（`RewardedRescue.request(purpose: .hint, guardedBy: .checkedByGrant)`・局ガードは `gameSerial`）。
回数と順位表の扱いは `CoreEngine/BoardHintBudget` に 1 つだけ置き、4 本が同じ勘定に乗る。
ボタンは持たず、対局中の操作列の「⋯」メニュー（`Core/BoardGameControlBar.swift` の `BoardControlBarHint`・#1421）の
1 項目に入る（「ヒント（残り N 回）」。無料を使い切ったあとは「広告を見てヒント（残り N 回）」に変わる）。
**この「残り N」は広告でこれから足せる回数も含む表示で、上の「ボタンの回数表示と広告の補充」の共通ルール
（数字＝いま使える回数のみ）とは異なる。#1897 で変更予定**。

- **1 局 3 回は無料、使い切ったあとは広告 1 本につき 1 回、最大 5 回まで足せる（合計 8 回）**。
  1 局ごとに戻る（`newGame`・無料も広告も）。無料枠と広告枠は同じ `used` を共有する 1 本のカウンタで、
  無料が残っているうちは広告を要求しない（`hasFreeRemaining`）。8 回を使い切ると項目は押せなくなる。
  - 広告の経路は `requestAdHint()`（各ゲームの Model）。**広告の視聴完了を確かめてから CPU の読みを始める**
    （読み終えてから広告を流さない）。視聴のあいだに指す・待った・新規対局が入ったら回数を減らさず
    `.unavailable` を返し、「ヒントを出せませんでした」のアラートで知らせる（視聴しなかったときは「ヒントを表示できませんでした」）。
    広告の視聴中は同じメニューの「待った」も塞ぐ（2 本目のロード失敗で誤アラートが出るのを防ぐ）
  - 解析は `RewardedRescue.requestHandledByModel(withOutcome:)` で、`purpose` は既存の `hint`。
    したがって `reward_request` / `reward_ad`（`purpose = hint`）は出る。**`reward_offer` は出ない**
    （常設のメニュー項目で、確認を挟まずに広告へ進むため。ナンプレのヒントと同じ扱い。下の「提示の瞬間が無い面」）。
    無料の 1 回は広告を通らないので `reward_*` は出ない
- 押すと**既存の CPU 思考エンジンで最善手を 1 手だけ**求め、盤の上に紫の枠（`BoardGameHintColor`）で示す。
  読みは対局中の CPU の強さに関わらず**常に最強**（`BoardHintBudget.engineLevel`）。
  五目並べの level 0（弱）は探索せず確率で見逃すため、対局の強さに合わせると最善手にならない（#665）
- 読みは CPU の着手と同じ `AITurnGuarded` の照合に載せる（#531）。読みの最中に指す・待った・新規対局が
  入ったら印を出さず、**回数も減らさない**（ヒントが出ないのに 1 回使ったことにしない）。
  将棋・チェスは**成り選択中に返ってきた読みも捨てる**——そのとき `aiTurnKey` はまだ変わらないので
  キーの照合では弾けず、通すと直後の `apply` が印を消して「回数だけ減ってヒントが出ない」になる
- **ヒントを 1 回でも使った局は Game Center の順位表に送らない**（`GameScore.isLeaderboardEligible = false`。
  ソリティアのジョーカー #406 と同じ扱い）。**端末内の自己ベスト（`PlayRecord`）は使用の有無を問わず残る**。
  3 本とも決着へ渡す成績は `hints.winLossScore` の 1 経路に閉じる。
  なお 3 本の指標は `.winLoss` で、`GameCenterLeaderboard.score` は `.winLoss` を無条件に弾くため、
  **現時点では旗の有無に関わらず順位表へは送っていない**。この旗は将来 `.winLoss` に順位表を
  足したときに勝手に混ざらないための保証として先に立ててある
- 使った回数は中断データに持ち回る（`hintsUsed` は **Optional**。鍵を持たない v1.1.5 までの中断データは
  未使用として読む）。**盤の上の印は保存しない**（開き直したら出し直す）
- **ヒントのために増やしたイベントは無い**。使った回数（無料・広告の合計）は、進行中のプレイに覚えておき、
  終わりの `game_end` に `hints_used` として載せる（#1326。ヒントを使わなかったプレイでは鍵ごと送らない。
  `GameServices.gameDidUseHint` を呼ぶのはこの 3 本だけで、ナンプレ・麻雀ソリティアのヒントは載せない）。`game_start` / `game_end` の数え方には影響しない。広告での補充ぶんは上の `reward_request` /
  `reward_ad` が数える
- 3 本とも同じ部品・同じ見た目（電球のアイコン。「⋯」メニューの 1 項目）。
  パズル系（ナンプレ #262・麻雀ソリティア #336）のヒントは**最初から広告制**で、こちらは無料 3 回を持つ点が違う

#### マインスイーパー: ヒント（#2024・`release/v1.1.11`・会長決裁 2026-10-11）

盤の下の「操作の段」（#1856）に「ヒント」を置く。押すと、**開いている数字だけから理屈で安全と言えるマス**を探し、紫の枠
（`BoardGameHintColor`）で 1 つ光らせる（開けるのはプレイヤー）。理屈で決まるマスが無い（運任せの）局面では、開いているマスに
接する安全なマスを 1 つ**その場で開ける**。

- **回数は 1 盤 無料 1 回、使い切ったら広告 1 本で +1、広告は最大 3 回（合計 4 回）**。コンティニュー（`continueUsed`）とは別の回数。
  回数の勘定は `CoreEngine/BoardHintBudget`（`freeLimit` / `adLimit` を init で渡せる形に広げた。将棋・チェス・五目並べ・オセロは
  既定の 3 / 5 のままで挙動は変わらない）。値は `MinesweeperHintPolicy`。表示は上の「ボタンの回数表示と広告の補充」の共通ルール
  （無料の残りを「あと n 回」、使い切ったら「0回 ▶ 広告を見て +1」、広告まで使い切ったら「あと0回」で押せない）
- **押せるのは遊んでいる最中だけ**（最初の 1 手の前・決着後は不可）。新規ゲームで回数が戻る
- 推論は `MinesweeperHint`（SwiftUI 非依存の純粋関数）。「数字 = 確定地雷数なら残りは安全」「数字 = 未開の数なら全部地雷」の繰り返しと、
  2 つの数字の包含関係。**入力 `Observation` に地雷の有無を載せる口が無く、地雷の場所は推論に使えない**。**旗は推論に使わず**（間違いうる）、
  旗のマスは答えの候補から外す
- 運任せの局面で開けるときだけ `isMine` を見る（`MinesweeperModel.guessCell`）。開いたあとは通常の `floodReveal` → `settleAfterReveal` を通る。
  **答えが無いときは回数を減らさない**
- 広告は `RewardedRescue`（`purpose` は既存の `hint`）で、**視聴完了してから答えを求める**（`useAdHint(forGame:)`。広告を出す前に控えた
  `gameSerial` と照合し、視聴中に局が替わっていたら回数を減らさず「ヒントを出せませんでした」）。確認ダイアログは挟まない
  （常設の項目で広告へ進む。`reward_offer` は出ない＝ナンプレ・将棋等のヒントと同じ扱い）
- **ヒントを使った局は順位表に送らない**（コンティニューと同じ。`isLeaderboardEligible = !continueUsed && !hints.wasUsed`）。自己ベストは残る
- 使った回数は中断データに持ち回る（`hintsUsed` は Optional。鍵の無い旧形式は 0 回）。**光らせているマスは保存しない**。
  `GameServices.gameDidUseHint` で `game_end` の `hints_used`（1〜4）に載る

#### 神経衰弱: ヒント（#2026・`release/v1.1.11`・会長決裁 2026-10-11）

盤の下の「操作の段」（#1856）の「待った」の隣に「ヒント」を置く。**自分の番で 1 枚目をめくったあと**に押すと、その札の相方（同じ絵柄の、
まだ伏せてあるもう 1 枚）を紫の枠（`BoardGameHintColor`・裏面も紫なので白縁を挟んだ二重枠）で **1 秒**光らせて消す。めくるのはプレイヤー。

- **回数は 1 ゲーム 無料 1 回、使い切ったら広告 1 本で +1、広告は最大 3 回（合計 4 回）**。「待った」（`mattaUsed`）とは別の回数。
  勘定は `CoreEngine/BoardHintBudget`（`freeLimit` 1 / `adLimit` 3。値は `ConcentrationHintPolicy`）。表示は「ボタンの回数表示と広告の補充」の共通ルール
- **押せるのは自分の番の、1 枚目をめくったあと 2 枚目をめくる前だけ**（CPU の番・不一致の表示中・決着後・1 枚目の前・光っている間は不可）。
  押せない条件で押しても回数は減らない。新規ゲームで回数が戻る
- 答えは `cards` から同じ絵柄のもう 1 枚を引くだけ（`partnerIndex()`）。`hintIndex` は読むたびに「1 枚目と同じ絵柄・伏せ・未獲得」を確かめる
- 光らせる時間は Model が返し（`hintGlowDuration`）、View の `.task(id: hintRun)` が待って `finishHint(run:)` を呼ぶだけ（テストは実時間を待たない）。
  札をめくれば印は即座に消える
- 広告は `RewardedRescue`（`purpose: .hint`）で、視聴完了してから出す（`grantAdHint(forGame:first:)`）。広告を出す前に控えた `gameSerial` と
  1 枚目の札に照合し、**新規ゲーム・待ったで状況が変わっていたら印を出さず回数も減らさない**。確認ダイアログは挟まない
- 記録は勝敗のみなので順位表の扱いは変えない。使った回数は中断データに持ち回る（`hintsUsed` は Optional・鍵の無い旧形式は 0 回）。**印は保存しない**。
  `GameServices.gameDidUseHint` で `game_end` の `hints_used`（1〜4）に載る

#### ソリティア・スパイダー・フリーセル: ヒント（#2025・`release/v1.1.11`・会長決裁 2026-10-11）

盤の下の「操作の段」（#1856）の「戻す」の隣に「ヒント」を置く（3 本とも同じ作り）。押すと「考え中」で今の盤から**勝ち筋を探し、最初の 1 手**を、
**動かす札（紫の実線の枠）と行き先（紫の点線の枠）**で示す。動かすのはプレイヤー。山をめくる・配る手のときは山札に点線を重ねる（`BoardGameHintColor`）。

- **回数は 1 ゲーム 無料 3 回、使い切ったら広告 1 本で +1、広告は最大 5 回（合計 8 回）**（`BoardHintBudget` の既定。値は各ゲームの `…HintPolicy`）。
  **戻すでヒントの回数は戻らない**（別の回数）。新規ゲームで戻る。表示は「ボタンの回数表示と広告の補充」の共通ルール
- 探索は純関数（`FreeCellHint` / `SpiderHint` / `SolitaireHint`）が既存のソルバー（`FreeCellSolver` / `SpiderSolver` / `SolitaireSolver`）を呼ぶ。
  **ソリティアは裏札・山札の中身を知ったうえで解く**（会長承認）。ジョーカーは探索で使わない
  - フリーセルは安全な組札送り（`autoplaySafe`）を飛ばして本筋の手を示す（飛ばした送りが先に要る手のときはその送り）
  - スパイダー・ソリティアは**示した筋の続きを覚える**（`…HintTrail`）。示した手を指して盤が筋の続きに着いたら解き直さず次の手を示す
    （毎回解き直すと別の筋に乗り換えて往復し、ヒントの手だけでは勝てなかった）。外れたら解き直す
  - 探索上限: フリーセル・ソリティアは 6 万局面（既存の既定）、スパイダーは 1・2 スート 6 万・4 スート 4 万（Mac の `-O` 実測で 0.7 秒以内・`SpiderHint.maxStates`）
  - 上限で打ち切られたら（勝てるとも勝てないとも言えない）見込みの良い手: ソリティア・スパイダーは「組札へ送れる札（スパイダーは組の完成）→ 裏札をめくれる移動 →
    空き列を作る移動 →（スパイダーは同じスートに繋がる移動 →）山札」、フリーセルは評価値が最も良くなる手
- **探索を尽くして勝ち筋が無い盤は「この盤からは勝てません。戻すで戻れます」と出し、回数は減らさない**。広告の経路は**先に読む**ので、勝てない盤では広告を流さない
- 探索は `Task.detached`（持ち主は Model 1 つ）。**盤が動く・配り直し・画面を離れるで取り消し、結果は捨てる**（印を出さず回数も減らさない）。
  印は盤が動いたら消え、**保存しない**
- 広告は Model が読み → 広告 → 適用を 1 本の非同期メソッドで持つ（`requestAdHint()`・`RewardedRescue.requestHandledByModel(withOutcome:)`・`purpose: .hint`）。
  広告のあいだに盤・画面が変わっていたら回数を減らさず「ヒントを出せませんでした」。確認ダイアログは挟まない（`reward_offer` は出ない）
- **ヒントを使った局は順位表に送らない**（ジョーカーと同じ。`isLeaderboardEligible` に `!hints.wasUsed`）。自己ベストは残る
- 使った回数は中断データに持ち回る（`hintsUsed` は Optional。鍵の無い旧形式は 0 回）。`GameServices.gameDidUseHint` で `game_end` の `hints_used`（1〜8）に載る

#### バックギャモン: ヒント（#2302・`release/v1.1.12`・企画倉庫）

将棋・チェス・五目並べ・オセロ・囲碁と同じ仕組み（`BoardHintBudget`・無料 3 回＋広告で最大 5 回・合計 8 回）。盤の下は共通の `BoardGameControlBar`
（待った・ヒント・「⋯」）で、広告の無い**やり直しと投了は「⋯」に入る**。

- 押すと `BackgammonEngine`（`BoardHintBudget.engineLevel`＝むずかしい）が**残りの目に対する最善手順の先頭 1 手**を読み、
  **動かす駒を紫の輪・行き先を紫の三角（あがりは置き場）**で示す（`BoardGameHintColor`）。手順全体は示さず、指すと印は消える。続きは押し直す（1 回消費）
- 読みは `withAITurnGuard` の照合に載せる。読んでいるあいだに盤が動いたら印を出さず回数も減らさない。広告は視聴完了後に読む（`requestAdHint()`）
- 押せるのは自分の手番で動かせる手があるとき（パスの局面・CPU の手番・決着後は押せない）
- ヒントを使った局は順位表に送らない（`hints.winLossScore`）。使った回数は中断データに持ち回る（`hintsUsed` は Optional・鍵の無い旧形式は 0 回）。**印は保存しない**
- `GameServices.gameDidUseHint` で `game_end` の `hints_used`（1〜8）に載る。解析イベントは増やさない
